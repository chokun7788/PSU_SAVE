# Model Usage Policy

## ใช้กี่โมเดล

คำตอบคือขึ้นกับความหมายของคำว่า "โมเดล"

ถ้าหมายถึง LLM สำหรับตอบคำถาม:

- ใช้จริงควรมี LLM หลัก 1 ตัว เช่น `qwen3.5:4b`

ถ้าหมายถึงระบบ RAG ที่ครบขึ้น:

- ควรมี 2 โมเดลคนละหน้าที่

```text
1. Embedding model: ใช้ค้นข้อมูล
2. LLM: ใช้เรียบเรียงคำตอบ
```

## Production ที่แนะนำ

```text
Embedding: qwen3-embedding:0.6b
LLM: qwen3.5:4b
```

เหตุผล:

- embedding เล็กและทำหน้าที่ค้น semantic similarity
- Qwen3.5-4B ใช้ตอบ/สรุปจาก context
- แยกหน้าที่กัน ทำให้เร็วและแม่นกว่าให้ LLM ทำทุกอย่างเอง

## แล้ว qwen2.5:3b / qwen3:4b ต้องลบไหม

ยังไม่ต้องลบ

ตอนนี้ควรเก็บไว้เพื่อเทียบ:

- `qwen2.5:3b`: เร็ว เบา ใช้เป็น baseline
- `qwen3:4b`: ตัวที่มีอยู่แล้ว ใช้เทียบคุณภาพ
- `qwen3.5:4b`: candidate หลักสำหรับ RAG+LLM

เมื่อทดสอบเสร็จค่อยตัดสินใจลบตัวที่ไม่ได้ใช้จริง

## จะเปลี่ยนเป็น Qwen3.5 แล้วเสียอะไรไหม

อาจเสีย:

- ใช้พื้นที่เพิ่มประมาณ 3.4GB ถ้าใช้ Ollama `qwen3.5:4b`
- latency อาจสูงกว่า `qwen2.5:3b`
- format คำตอบอาจเปลี่ยน ทำให้ Ground Truth ที่เช็ค keyword แบบเดิมต้องตรวจซ้ำ
- ถ้า prompt ไม่ดี อาจตอบยาวหรือแต่งเพิ่มได้

ได้อะไร:

- สรุปภาษาไทย/อังกฤษดีขึ้น
- เหมาะกับคำถามที่ไม่ใช่ fact ตรงๆ
- เหมาะกับ RAG ที่ต้องเอาหลาย context มารวม

## กฎการเลือกโมเดล

ใช้ `rule/fact card/calculator` ก่อนเสมอเมื่อคำถามเป็น:

- ราคา
- เวลาเปิดปิด
- วันหยุด
- จำนวนคน
- กฎที่มีคำตอบชัด
- ค่าปรับ

ใช้ Qwen3.5 เมื่อคำถามเป็น:

- สรุป
- อธิบาย
- เปรียบเทียบ
- ถามหลายเงื่อนไขพร้อมกัน
- ถามแบบภาษาคนที่ต้องเรียบเรียงจากหลาย chunk

## ไม่ควรทำ

- ไม่ควรเอาข้อมูลทั้งหมดใส่ prompt ตรงๆ
- ไม่ควรให้ LLM ตอบราคา/กฎจากความจำ
- ไม่ควร fine-tune ตั้งแต่แรก
- ไม่ควรลบโมเดลเก่าก่อนทดสอบ latency/quality

## คำสั่งที่เกี่ยวข้อง

โหลด Qwen3.5:

```powershell
ollama pull qwen3.5:4b
```

โหลด embedding:

```powershell
ollama pull qwen3-embedding:0.6b
```

เทียบโมเดล:

```powershell
py -3 tools\05_compare_models.py --models qwen2.5:3b qwen3:4b qwen3.5:4b
```
