# 02 — ข้อมูลและหมวดหมู่ที่ใช้ทำบอท

ข้อมูลในโปรเจกต์นี้มาจากเว็บไซต์หลักและระบบจองของ PSU Esports Studio - Phuket

---

## 1. ไฟล์ข้อมูลหลัก

### faq_facts.jsonl

ตำแหน่ง:

```text
data/curated/faq_facts.jsonl
```

เป็นข้อมูลที่จัดรูปแบบเองจากเว็บ เหมาะมากสำหรับคำถามที่ต้องการคำตอบตรง เช่น:

- จองได้กี่ session
- เช็คอินล่วงหน้าได้กี่นาที
- PC มีเกมอะไร
- PS5 มีเกมอะไร
- VR Station มีเกมอะไร
- ช่องทางติดต่อคืออะไร

เวลา build index ควรใส่ไฟล์นี้ก่อนหรือให้น้ำหนักสูงกว่าข้อมูลเว็บดิบ

### all_chunks.jsonl

ตำแหน่ง:

```text
data/processed/all_chunks.jsonl
```

ใช้สำหรับทำ RAG โดยตรง เพราะข้อมูลถูกแบ่งเป็น chunk แล้ว

field สำคัญ:

| field | ความหมาย |
|---|---|
| `id` | รหัส chunk |
| `category` | หมวดหลัก เช่น reservation, services |
| `subcategory` | หมวดย่อย |
| `tags` | tag ช่วยค้น |
| `title` | ชื่อหน้า |
| `url` | แหล่งที่มา |
| `text` | เนื้อหาหลักที่ใช้ตอบ |
| `metadata.category_label_th` | ชื่อหมวดภาษาไทย |

### all_pages.jsonl

ตำแหน่ง:

```text
data/processed/all_pages.jsonl
```

ใช้เมื่อต้องการดูข้อมูลระดับหน้าเว็บ ไม่ได้แบ่ง chunk

## 2. หมวดข้อมูล

| category | ความหมาย | ใช้ตอบเรื่อง |
|---|---|---|
| `reservation` | ระบบจองและกฎการจอง | วิธีจอง กฎจอง เช็คอิน ยกเลิก ค่าปรับ |
| `services` | บริการ อุปกรณ์ และเกม | PC, PS5, Switch, VR, Cockpit, รายชื่อเกม |
| `competition` | การแข่งขันและกิจกรรมอีสปอร์ต | รายการแข่ง กิจกรรม challenge tournament |
| `training` | การอบรมและกิจกรรมเรียนรู้ | กิจกรรมอบรม หลักสูตร Garena Academy |
| `news` | ข่าวสาร | ข่าวกิจกรรมรายเดือน/รายปี |
| `knowledge` | ความรู้อีสปอร์ต | Esports คืออะไร ประเภทเกม อาชีพ เกมตัวอย่าง |
| `about_us` | ข้อมูลศูนย์ | สมาชิก แกลเลอรี ดาวน์โหลด |
| `contact` | ติดต่อ | เบอร์ อีเมล Facebook ที่อยู่ |
| `policies` | นโยบาย | Privacy, Cookie, Website Security |
| `main` | หน้าหลัก | ภาพรวมศูนย์ |

---

## 3. ควรใช้หมวดไหนก่อน

สำหรับบอทเวอร์ชันแรก แนะนำใช้:

```text
reservation
services
competition
knowledge
contact
```

เหตุผล:

- เป็นข้อมูลที่ผู้ใช้มีโอกาสถามบ่อย
- ข้อมูลไม่กระจัดกระจายเท่าหมวดข่าว
- กฎและบริการต้องตอบแม่น

หมวด `news` ควรเพิ่มทีหลัง เมื่อ retrieval เริ่มนิ่งแล้ว

---

## 4. วิธี filter ข้อมูลก่อน build index

ถ้าใช้ Python:

```python
allowed_categories = {"reservation", "services", "competition", "knowledge", "contact"}

records = []
with open("data/processed/all_chunks.jsonl", encoding="utf-8") as f:
    for line in f:
        item = json.loads(line)
        if item["category"] in allowed_categories:
            records.append(item)
```

## 5. Metadata ที่ควรเก็บใน Vector DB

เวลาเอา chunk ลง vector database ให้เก็บ metadata นี้ด้วย:

```json
{
  "chunk_id": "...",
  "category": "reservation",
  "subcategory": "reservation_system",
  "title": "...",
  "url": "...",
  "tags": ["reservation", "rules"],
  "category_label_th": "ระบบจองและกฎการจอง"
}
```

ประโยชน์:

- ใช้ filter ตามหมวด
- ใช้แสดง citation
- ใช้ debug ว่าบอทตอบจากหน้าไหน
- ใช้ routing ถ้าคำถามชัดว่าเป็นเรื่องจอง/เกม/แข่งขัน

---

## 6. แนวคิด routing ตามคำถาม

ก่อนค้น สามารถเดาหมวดจากคำถามได้

ตัวอย่าง:

| คำถามมีคำว่า | ควรค้นหมวด |
|---|---|
| จอง, session, เช็คอิน, ยกเลิก, ค่าปรับ | reservation |
| เกม, PC, PS5, Switch, VR, Cockpit | services |
| แข่งขัน, tournament, RoV, Valorant, Tekken, CS2 | competition + news |
| esports คืออะไร, อาชีพ, ประเภทเกม | knowledge |
| เบอร์, อีเมล, ติดต่อ, Facebook | contact |

MVP อาจยังไม่ต้อง routing ก็ได้ ให้ค้นทุกหมวดก่อน แต่เมื่อข้อมูลเยอะขึ้น routing จะช่วยลด noise
