## Adaptive LLM Latency Gate

- พบว่าแม้ `LLM-first intent` ถูก skip สำหรับ route ที่มั่นใจสูงแล้ว แต่ threshold ปกติยังเรียก LLM intent ซ้ำเมื่อ heuristic confidence ต่ำกว่า 0.88 ทำให้คำถามง่ายอย่าง `เกมตอนนี้มีเกมอะไรบ้าง` ใช้เวลาประมาณ 11 วินาที
- เพิ่ม gate `PSU_INTENT_LLM_FIRST_ONLY_WEAK=1` ใน `app/pipeline/universal_intent.py`: ถ้า route อยู่ในหมวด high-trust และ heuristic มั่นใจพอ จะไม่เรียก LLM intent แม้เปิด `-IntentFirst`
- ปรับ threshold เรียก LLM intent ปกติจาก 0.88 เป็น 0.80 เพื่อลดการเรียก LLM ในคำถามที่ heuristic ตีได้พอแล้ว
- ปรับ default local runner ให้ `facts composer` ปิดไว้ก่อนเพื่อความเร็ว และเปิดเองได้ด้วย `-Composer` หรือ `--composer` เมื่อต้องการให้ LLM ช่วยเรียบเรียงคำตอบ
- ผลหลังปรับ: `เกมตอนนี้มีเกมอะไรบ้าง` ใช้ heuristic intent และลดจากประมาณ 11.5 วินาทีเหลือประมาณ 3.7 วินาทีใน cold run, `คนดูแลศูนย์มีใครบ้าง` เหลือประมาณ 1.5 วินาทีใน cold run
- วัดใน process เดียวแบบใกล้ chat loop จริง: `คนดูแลศูนย์มีใครบ้าง` ประมาณ 0.24 วินาที, `Nintendo มีเกมอะไรบ้าง` ประมาณ 2.03 วินาที, ส่วนคำถาม general ที่ต้องใช้ LLM เช่น `เมืองหลวงประเทศไทยคืออะไร` ยังใช้ประมาณ 8 วินาที

## Adaptive Intent LLM Review

- ปรับแนวคิดจาก `strong route = skip LLM` เป็น `exact route = skip LLM, broad/ambiguous route = ให้ Intent LLM review`
- เพิ่ม broad-review gate ใน `app/pipeline/universal_intent.py` สำหรับ operation กว้าง เช่น `list`, `detail`, `how_to`, `availability`, `recommendation`, `unknown` และ route กว้าง เช่น members/games/equipment/knowledge lookup
- เพิ่ม competing-domain detection: ถ้าคำถามมีสัญญาณชนหลายหมวด เช่น เกม+อุปกรณ์ หรือจอง+ราคา จะพิจารณาส่งให้ Intent LLM ยกเว้น operation ที่ exact มาก เช่น `price_calculate`, `control`, `schedule_lookup`, `role_lookup`, `group_count`
- แก้บั๊ก metadata gate ที่ทำให้เหตุผล `ควร review ด้วย LLM` ไปบล็อกการเรียก LLM เอง โดยแยก `llm_first_skip_reason` และ `llm_first_review_reason`
- ย่อ prompt ของ Intent LLM และเปิด Ollama JSON mode เพื่อลด token และทำให้ parse JSON เสถียรขึ้น
- ลด default `IntentPredict` จาก 120 เหลือ 80 เพราะ intent classification ต้องการ JSON สั้น ๆ ไม่ใช่คำตอบยาว
- เพิ่ม sanitize: ถ้า LLM ส่ง `equipment/control` จะปรับเป็น `equipment/how_to` เพราะ `control` ควรใช้กับ game controller/buttons เท่านั้น
- เพิ่ม regression test `tests/smoke_test_adaptive_intent_gate.py`
- ผลทดสอบหลังปรับ: `เกมตอนนี้มีเกมอะไรบ้าง` ได้ intent `games/list` จาก `llm`, `คนดูแลศูนย์มีใครบ้าง` ได้ `members/list` จาก `llm`, `อยากเล่นรถแข่งต้องใช้อะไร` ได้ `equipment/how_to` จาก `llm`, ส่วน `ถ้าจอง PS5 ตั้งแต่ 9โมงถึง11โมงเสียกี่บาท` ยังใช้ heuristic/calculator ไม่เสียเวลา intent LLM
