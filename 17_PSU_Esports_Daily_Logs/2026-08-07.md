### ปัญหาและ Root Cause

- Full Process Flow เดิมครอบคลุมองค์ประกอบครบ แต่ตั้งใจเป็น architecture overview จึงยังไม่อธิบายความหมายของศัพท์ วิธีคำนวณคะแนน เงื่อนไขผ่าน/ไม่ผ่าน และตัวอย่างการไหลของ request มากพอสำหรับผู้อ่านที่ยังไม่คุ้นกับระบบ chatbot/RAG/LLM
- Root cause ของความสับสนคือชื่อ process บางส่วนเป็นคำมาตรฐานกว้าง ๆ แต่ implementation ปัจจุบันใช้ deterministic rules หรือ heuristic เฉพาะระบบ ไม่ได้ใช้ model ทุกจุด
- พบรายละเอียดที่ต้องระบุให้ตรง source ได้แก่ `assess_sources()` คืน `stale=False` เสมอ, numeric conflict เป็น heuristic แบบนับค่าตัวเลข, curated retrieval ยังไม่ใช่ BM25 library และ Shadow Critic ไม่ได้อยู่ใน synchronous user-answer path ปกติ
