## เพิ่มเติมช่วงท้ายวัน: Experimental RAG Fallback

ผู้ใช้ต้องการลองตัดการปฏิเสธแบบ no-answer ออกบางส่วน แล้วให้ระบบลองใช้ RAG/LLM ตอบแทน เพื่อดูว่าคำตอบนอก rulebase จะดีขึ้นไหม

สิ่งที่ทำ:

- เพิ่ม `app/pipeline/experimental_fallback.py`
- เพิ่ม flag `experimental_rag_fallback` และ `experimental_allow_llm` ใน pipeline/API
- ปรับ `app/pipeline/engine.py` ให้ fallback จาก no-answer/guard no-answer ไปหา experimental RAG fallback ได้
- ปรับ `app/pipeline/router.py` ไม่ให้คำถามอย่าง `อยากจัดวันเกิดที่ศูนย์ได้ไหม` ถูก broad news/event route แย่ง
- ปรับ `/api/chat` ทั้งในโฟลเดอร์ 18 และ 20 ให้รับ flag ทดลอง
- ปรับ `web_chat/app.js` และ `20/app.js` ให้หน้าเว็บส่ง flag ทดลองไปกับคำถาม

พฤติกรรมใหม่ในโหมดทดลอง:

- `มีให้เช่าจอไปบ้านไหม` จากเดิม no-answer -> ตอบข้อมูลที่ยืนยันได้เรื่อง Gaming Monitor ใน PC Zone และบอกว่ายังไม่มีข้อมูลยืนยันเรื่องเช่า/ยืมออกนอกสถานที่
- `รับซ่อมคอมส่วนตัวไหม` จากเดิม no-answer -> ตอบข้อมูลที่ยืนยันได้เรื่อง Gaming PC ใน PC Zone และบอกว่ายังไม่มีข้อมูลยืนยันเรื่องรับซ่อมคอมส่วนตัว
- `อยากจัดวันเกิดที่ศูนย์ได้ไหม` จากเดิม no-answer -> ตอบข้อมูลที่ยืนยันได้เรื่องระบบจองเข้าใช้บริการเป็นรอบเวลา และบอกว่ายังไม่มีข้อมูลยืนยันเรื่องงานวันเกิด/ปาร์ตี้/อีเวนต์ส่วนตัว
- `มีคอร์สสอนเล่น Valorant ไหม` จากเดิม no-answer -> ตอบข้อมูลที่ยืนยันได้ว่า VALORANT มีให้เล่นใน PC Zone และบอกว่ายังไม่มีข้อมูลยืนยันเรื่องคอร์สสอนเล่น

- `ถ้าใช้บัตรนักศึกษาจะเล่นฟรีใช่ไหม`
- `รายกรแข่งมีอะไรบ้าง`
- `ROV แข่งชนะได้เงินเท่าไหร่`
- `มีคอมให้เล่นไหม`
- `เอาของกินเข้าไปกินได้ไมห`

สิ่งที่ทำ:

- เพิ่ม normalization/alias เช่น `รายกร -> รายการ`, `ไมห/ใหม -> ไหม`, `ของกิน/ข้าว -> อาหาร`, `บัตรนศ -> บัตรนักศึกษา`, `สเตป/step -> ขั้น`, `พีซี -> pc`
- เพิ่ม route เฉพาะสำหรับ student/free service fee, PC availability, competition prize no-answer, competition game list phrase, และ food/rules alias
- เพิ่มคำตอบ fast path สำหรับ:
  - บัตรนักศึกษา/เล่นฟรี
  - ไม่มีบัตรนักศึกษาตอนจอง
  - จองขั้นที่ 1-5
  - มีคอมให้เล่นไหม
  - เงินรางวัลการแข่งขันที่ไม่มีข้อมูลจริง
- ปรับ wording no-answer ของคอร์สสอนเล่นเกมให้สุภาพและโยงเกมเฉพาะ เช่น RoV / VALORANT

- `app/core/normalization.py`

- `app/runtime/fast_answer.py`
- `data/rules/no_answer_rules.jsonl`

## เพิ่มเติม: Fuzzy Normalization แบบคุมขอบเขตสำหรับคำ intent สำคัญ

ผู้ใช้ต้องการให้ระบบรองรับคำสะกดเพี้ยนใกล้เคียง ไม่ต้องรอเพิ่ม alias ทีละคำ เช่น `รายกานแข่งขันมีอะไรบ้าง` ควรถูกมองเป็น `รายการแข่งขันมีอะไรบ้าง`

สิ่งที่ทำ:

- เพิ่ม fuzzy normalization ใน `app/core/normalization.py` ทั้งโฟลเดอร์ 18 และ 20
- ใช้ `SequenceMatcher` กับคำ intent สำคัญ เช่น `รายการ`, `แข่งขัน`, `บริการ`, `นักศึกษา`, `อุปกรณ์`, `อาหาร`, `กติกา`, `รางวัล`, `ขั้นตอน`
- จำกัดให้ทำเฉพาะข้อความสั้นไม่เกิน 160 ตัวอักษร เพื่อไม่ให้ retrieval ช้าเมื่อต้อง normalize ข้อความฐานข้อมูลยาว ๆ
- เพิ่ม prefix guard เช่น คำที่จะกลายเป็น `รายการ` ต้องขึ้นต้นใกล้ `รายก` เพื่อลดการแก้คำกลางประโยคมั่ว
- จำกัด fuzzy เป็นความยาวเท่าคำเป้าหมาย เพื่อกันปัญหากลืนตัวอักษรถัดไป เช่น `รายการแข่งขัน` ถูกแก้พัง

ผลทดสอบแบบเจาะจงจากไฟล์ UTF-8:

- `รายกานแข่งขันมีอะไรบ้าง` -> normalize เป็น `รายการแข่งขันมีอะไรบ้าง`
- `รายกานแข่งตอนนี้มีอะไรบ้าง` -> normalize เป็น `รายการแข่งตอนนี้มีอะไรบ้าง`
- `รายการแข่งขันมีอะไรบ้าง` -> ยังเป็น `รายการแข่งขันมีอะไรบ้าง`
- route เข้า `games/competition_game_list`
- mode เป็น `pipeline:competition_game_list_fast_path`
- compile ผ่านทั้งโฟลเดอร์ 18 และ 20
- ไม่ได้ run Ground Truth ตามคำสั่งผู้ใช้

ข้อจำกัด:

- ไม่ได้เปิด PyThaiNLP เป็น default เพราะเคยทดสอบแล้ว cold start ช้ามากบน production
- fuzzy นี้ตั้งใจแก้เฉพาะคำ intent หลัก ไม่ใช่ spell correct ภาษาไทยทุกคำ
- คำสั้นมาก เช่น `จอง`, `เกม`, `เปิด` ยังไม่ทำ fuzzy กว้าง ๆ เพราะเสี่ยงแก้คำถูกให้พังหรือ route ผิด

## เพิ่มเติม: ตั้งค่า PowerShell UTF-8 ถาวร

ผู้ใช้พบว่า PowerShell มีปัญหากับภาษาไทย โดยเฉพาะการ pipe ข้อความภาษาไทยเข้า Python/command ทำให้คำถามเพี้ยนเป็น `?` หรือ mojibake

สาเหตุที่ตรวจพบ:

- `$OutputEncoding` เดิมเป็น `us-ascii`
- `[Console]::InputEncoding` เดิมเป็น `IBM437`
- `chcp` เดิมเป็น code page `437`
- ทำให้ภาษาไทยเสียหายเมื่อส่งผ่าน pipeline/inline command

สิ่งที่ทำ:

- สร้าง PowerShell profile แบบ CurrentUserAllHosts:
  - `C:\Users\Chokhun\OneDrive\เอกสาร\WindowsPowerShell\profile.ps1`
- ตั้งค่าอัตโนมัติทุกครั้งที่เปิด Windows PowerShell:
  - `[Console]::InputEncoding = UTF-8`
  - `[Console]::OutputEncoding = UTF-8`
  - `$OutputEncoding = UTF-8`
  - `$env:PYTHONIOENCODING = "utf-8"`
  - `$env:PYTHONUTF8 = "1"`
  - `chcp 65001`

ผลทดสอบ:

- เปิด PowerShell process ใหม่แล้วได้:
  - `$OutputEncoding` = `utf-8`
  - `[Console]::OutputEncoding` = `utf-8`
  - `[Console]::InputEncoding` = `utf-8`
  - `PYTHONIOENCODING` = `utf-8`
  - `PYTHONUTF8` = `1`
  - active code page = `65001`
- ทดสอบ pipe ภาษาไทยเข้า Python แล้วแสดงผล `รายกานแข่งขันมีอะไรบ้าง` ถูกต้อง

หมายเหตุ:

- เครื่องนี้มี Windows PowerShell 5.1 และไม่พบ `pwsh` 7
- ถ้าเปิด terminal ที่ใช้ `-NoProfile` profile นี้จะไม่ถูกโหลด ต้องเปิด PowerShell ปกติ
