# Daily Log - 2026-07-22

## Candidate-Based Intent LLM

- ปรับ Intent LLM จากการให้เลือก `domain/operation` จากรายการใหญ่ทั้งระบบ เป็น candidate-based selection ให้ LLM เลือกจากตัวเลือก 3-6 ตัวที่ระบบสร้างไว้ก่อน
- เพิ่ม candidate builder ใน `app/pipeline/universal_intent.py` โดยใช้ heuristic fallback, router category, domain keyword scores, operation keyword scores และ phrase เฉพาะ เช่น racing/cockpit, staff/member, MOBA, controller/buttons
- เปลี่ยน prompt ของ Intent LLM ให้สั้นลงมากและให้ตอบเพียง `candidate_id`, `confidence`, `reason` เพื่อลดเวลาและลด JSON parse failure
- ถอด Ollama `format=json` ออกจาก Intent LLM เพราะพบว่า Qwen สร้าง JSON ยาวจน `done_reason=length` และ parse ไม่จบ แต่ถ้าไม่บังคับ JSON mode จะตอบ JSON สั้นได้เร็วกว่า
- ลด default `IntentPredict` เหลือ 50 เพราะ intent selection ไม่ควรต้อง generate ยาว
- เพิ่ม in-process intent cache ใน `app/pipeline/universal_intent.py` เพื่อไม่เรียก Ollama ซ้ำเมื่อ normalized query, route, fallback และ candidate set เดิม
- ไม่ cache ผลล้มเหลวของ Intent LLM เพื่อไม่ให้ timeout/invalid JSON รอบหนึ่งทำให้คำถามเดิมพังในรอบต่อไป
- ผลทดสอบ: `อยากเล่นรถแข่งต้องใช้อะไร` ได้ intent `equipment/how_to` จาก LLM candidate และตอบผ่าน `related_guidance_fast_path`
- ผลทดสอบ: `เกมแนวตีป้อมมีอะไรบ้าง` ได้ intent `games/list` จาก LLM candidate แทน heuristic เดิมที่มองเป็น equipment/list
- ผลทดสอบ: `ถ้าจอง PS5 ตั้งแต่ 9โมงถึง11โมงเสียกี่บาท` ยังใช้ heuristic/calculator ไม่เข้า Intent LLM
- Cache test ใน process เดียวกัน: `อยากเล่นรถแข่งต้องใช้อะไร` รอบแรกประมาณ 2.7 วินาที รอบสองประมาณ 0.2 วินาที
- Regression tests ที่รันผ่าน: `tests/smoke_test_adaptive_intent_gate.py`, `tests/smoke_test_universal_intent.py`

## Routing Priority Baseline

- เพิ่มข้อมูล routing ชุดแรกใน `data/routing/`
  - `intent_catalog.jsonl`: catalog ของ intent/domain/operation พร้อม positive/negative examples
  - `route_priority_matrix.json`: priority rules สำหรับคู่ชน เช่น price vs games, booking vs games, controls vs game detail, members vs games, rules/penalty vs general/price/control
  - `routing_eval_cases.jsonl`: golden routing eval 40 ข้อ ครอบคลุม service fee, games, controls, reservation, members, equipment, schedule, rules, penalty และ general
- เพิ่ม `app/pipeline/routing_policy.py` เพื่ออ่าน priority matrix แล้ว override route แบบ data-driven เมื่อพบ keyword/entity conflict
- เสียบ routing policy ใน `_select_active_preprocessed_query()` เพื่อแก้ route ก่อนเข้า universal intent/structured/fast handlers
- ปรับ `app/pipeline/universal_intent.py`
  - ถ้า operation เป็น price หรือ route เป็น service fee ให้ domain เป็น `service_fee` ไม่ให้ game alias ดึงกลับไป `games`
  - เพิ่ม domain `rules` และ `penalty`
  - lock reservation/equipment/schedule/rules/penalty domain เมื่อ router เดิมเลือกหมวดนั้นแล้ว
  - map game availability route ให้ universal operation เป็น `availability`
- ปรับ `app/pipeline/tool_preconditions.py` และ `app/pipeline/engine.py` เพื่อกันคำถาม damage/penalty เช่น `ทำจอยพังโดนปรับเท่าไหร่` ไม่ให้โดน structured game controls แย่งตอบ
- ปรับ final route ของ structured modes สำคัญ เช่น `structured_games_catalog -> games/list`, `structured_equipment_catalog -> equipment/list`, `structured_members_group_count -> overview/group_count`
