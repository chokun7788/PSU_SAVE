## Latest Update - Latency Hardening, Warmup และ RAG Timeout Policy

### สรุปสิ่งที่ทำ

- แก้ root cause ของ latency ที่พบจาก profiler ไม่ได้แก้ expected result หรือปิด validator เพื่อให้ผลผ่าน
- แยก timing trace ของ hybrid retrieval เป็น curated retrieval, vector retrieval, merge/score, document reranker และ evidence packer
- เพิ่มคำถาม knowledge/news ใน startup warmup เพื่อให้ vector scan ที่ cold ไม่เกิดเป็น user request แรกของ domain เหล่านี้
- reuse ผลจาก hybrid retrieval ใน vector fallback เพื่อไม่เรียก vector scan ซ้ำใน request เดียว
- เปลี่ยน Ollama ของ facts composer และ experimental RAG ให้ใช้ streaming response, `keep_alive` และปิด socket เมื่อ timeout เพื่อให้ cancellation เป็น best-effort ที่แน่นขึ้น

### ปัญหาและ root cause

- ก่อนแก้ knowledge query บางเคสทำ vector scan ครั้งแรกประมาณ `3.9-4.1s` แล้วเรียก vector retrieval ซ้ำอีกประมาณ `140ms` หลัง hybrid guard ไม่ผ่าน
- Typhoon บนเครื่องปัจจุบันใช้เวลาประมาณ `6s` แม้ prompt สั้นมาก และ grounded composer ใช้ประมาณ `7.15-7.27s` ในรอบที่ตอบสำเร็จ

- BGE cold start ยังหนักมาก จึงยังต้อง warm นอก user request

### ผล BGE reranker และ root cause

- `BAAI/bge-reranker-v2-m3` ทำงานจริงและจัดอันดับเอกสารประวัติอีสปอร์ตได้ถูกต้อง (`bge_reranked`)

- Root cause คือ `_load_model()` ถูกเรียกครั้งแรกภายใน request และเดิมไม่มี cold-start budget guard
- เพิ่ม `PSU_DOCUMENT_RERANKER_COLD_START_MIN_REMAINING_SEC=30` และ trace `skipped_cold_start`; process ที่ warm แล้วจึงค่อย rerank ใน request
