## Ambiguity Gate / Risk Gate Before Structured-Fast

สรุป: เพิ่มด่าน `ambiguity_gate` หลัง route/intent/tool-router และก่อน structured/fast เพื่อลดเคสที่ router มั่นใจเกินไปแล้วตอบจากหมวดผิด โดยเฉพาะคำถามที่ไม่มี target พอ

สิ่งที่ทำ:
- เพิ่ม `app/pipeline/ambiguity_gate.py`
  - ตรวจ price query ที่ไม่มีบริการ/โซน/ชื่อเกม เช่น `ราคาเท่าไหร่`, `แล้วราคาเท่าไหร่`
  - ตรวจ short follow-up ที่ไม่มี target หลัง session resolver แล้ว
  - ตรวจคำถามกว้างเกินไป เช่น `มีอะไรบ้าง`
  - ถ้าเสี่ยงสูงจะคืน clarification ทันที ไม่ปล่อยไป structured/fast/RAG
  - ถ้าเสี่ยงต่ำจะปล่อยผ่านแต่เพิ่ม trace flag เช่น `price_query_with_game_target_requires_zone_mapping`
- เสียบ gate ใน `app/pipeline/engine.py`
  - ตำแหน่งหลัง `resolve_tool_routing()`
  - ก่อน `build_candidate_decisions()`, `evaluate_structured_tool_precondition()`, structured tool และ deterministic fast path
  - ผลลัพธ์ clarify ใช้ mode `pipeline:ambiguity_clarification`
- เพิ่ม `tests/smoke_test_ambiguity_gate.py`
  - `ราคาเท่าไหร่` ต้องถามกลับ ไม่ดึงราคา/นโยบายมั่ว
  - `แล้วราคาเท่าไหร่` ต้องถามกลับถ้าไม่มี context
  - `มีอะไรบ้าง` ต้องถามกลับ ไม่ default เป็น equipment catalog
  - `PS5 ราคาเท่าไหร่` ยังตอบ deterministic calculator
  - `Tekken 8 ราคาเท่าไหร่` ยังตอบ structured service fee by game
  - `จองยังไง` ยังตอบขั้นตอนจองตามปกติ

## LLM Health Manager / Circuit Breaker

สรุป: เพิ่มระบบ health/circuit breaker สำหรับ Local LLM เพื่อกัน timeout ซ้ำ ๆ และไม่ให้คำถามผู้ใช้ต้องรอ LLM ที่ไม่พร้อม

## สิ่งที่ทำ

- เพิ่ม `app/pipeline/llm_health.py`
  - เก็บ health state ต่อ model และต่อ LLM kind
  - มี `llm_call_allowed()` สำหรับถามก่อนเรียก LLM จริง
  - มี `record_llm_success()` และ `record_llm_failure()` สำหรับปรับสถานะหลัง call
  - มี `open_llm_circuit()` สำหรับเปิด circuit ทันที เช่น preflight fail
  - มี `preflight_ollama()` สำหรับยิง prompt สั้นตอน startup
  - มี `llm_health_snapshot()` สำหรับ debug/web health/local CLI
  - default:
    - `PSU_LLM_HEALTH_MANAGER=1`
    - failure threshold = 2
    - cooldown = 90s
    - preflight timeout = 5s
- ผูก health manager เข้ากับ LLM paths:
  - `app/pipeline/universal_intent.py`
    - adaptive intent LLM ถ้า circuit เปิด จะ skip และกลับ heuristic
    - cache hit ยังใช้ได้ เพราะไม่เรียก LLM จริง
  - `app/pipeline/llm_tool_router.py`
    - ถ้า circuit เปิด จะกลับ heuristic tool routing ทันที
  - `app/pipeline/facts_composer.py`
    - ถ้า circuit เปิด จะคืน draft answer ทันที ไม่รอ composer
  - `app/pipeline/experimental_fallback.py`
    - general LLM และ RAG LLM ถ้า circuit เปิด จะ skip แล้วตอบ unavailable/direct fallback ตาม path
- ผูก preflight เข้ากับ runtime:
  - `tools/local_ai_chat.py`
    - startup preflight หลัง warmup ถ้า `allow_llm=True`
    - เพิ่มคำสั่ง `/llm-health`
  - `app/web_api/server.py`
    - startup preflight
    - `/health` แสดง `llm_preflight` และ `llm_health`

## Behavior ที่ได้

- ถ้า LLM timeout/empty/no-parse เกิน threshold:
  - model เข้าสู่ cooldown
  - LLM path อื่น ๆ จะไม่เรียก Ollama ซ้ำระหว่าง cooldown
  - PSU structured/fast/RAG path ยังทำงานตามปกติ
- ถ้า preflight fail:
  - เปิด circuit ทันที
  - เหมาะกับเคสเปิดแชทแล้ว model cold load/queue ช้า
- ถ้าถาม general knowledge ตอน LLM cooldown:
  - ไม่รอ timeout
  - ตอบว่า general LLM ยังไม่พร้อม
- ถ้า facts composer เปิดอยู่แต่ LLM cooldown:
  - ใช้ structured draft เดิม
  - ไม่เสียเวลาเรียบเรียงด้วย LLM
