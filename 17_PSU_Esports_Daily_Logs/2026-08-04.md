## Latest Update - วิเคราะห์จุดใช้ Local LLM ที่เหมาะกับระบบปัจจุบัน

### วิเคราะห์อะไรไปบ้าง

- อ่าน handoff และเทียบ architecture ปัจจุบันกับโค้ดจริงของ pipeline
- วิเคราะห์ capability registry, policy veto, intent LLM, tool router, facts composer, RAG fallback, vector retrieval และ entity reranker
- เทียบกับผล Core PSU benchmark 1,325 ข้อที่ผ่านด้วย No-LLM 100% เพื่อแยกจุดที่ไม่ควรเพิ่ม LLM กับจุดที่ยังได้ประโยชน์จาก LLM
- ประเมินความเสี่ยงด้าน latency, hallucination, JSON parse, target ผิด, source หลุด และ sequential LLM calls

### ข้อเสนอหลัก

- คงคำถาม PSU ที่ชัดเจนไว้บน Structured/Fast/RAG แบบไม่เรียก LLM
- เพิ่ม LLM Query Planner สำหรับ compound question, weak route, ภาษาพูด และ query rewrite
- ใช้ Grounded Composer เฉพาะคำตอบหลายส่วนหรือหลาย source โดยห้ามเพิ่ม facts
- ใช้ LLM ช่วย follow-up เฉพาะเมื่อ deterministic session resolver ไม่มั่นใจ
- เปิด Entity Reranker เฉพาะ low-margin/family ambiguity ไม่เปิดทุกคำถาม
- ใช้ LLM Shadow Critic และ log analysis แบบเบื้องหลังเพื่อหาคำถามที่ระบบพลาด โดยไม่เพิ่ม latency ผู้ใช้
