# PSU Esports Chatbot: Local Owner Package

ชุดนี้คือหน้าเว็บ Chatbot สำหรับเปิดใช้บนเครื่องของผู้ดูแล โดยข้อมูลคำถามและประวัติการใช้งานจะอยู่ในเครื่องนี้ ไม่ได้เรียก Cloud Chatbot API และไม่เปิดรับการเชื่อมต่อจากเครื่องอื่น

เวอร์ชันที่ระบุใน `package_manifest.json` เป็นชุดให้เจ้าของทดลองและตรวจคำตอบ ยังไม่ควรประกาศเป็นระบบ Production จนกว่าจะเทียบสถานะจองรายช่องกับข้อมูลจริง ยืนยันนโยบายที่ค้าง ตรวจคำแปลอังกฤษ และทดสอบภาระใช้งานพร้อมกัน

## ก่อนเริ่มครั้งแรก

1. ติดตั้ง Python 3.11 หรือใหม่กว่า โดยเปิดตัวเลือก **Add Python to PATH** ระหว่างติดตั้ง
2. ติดตั้ง Ollama จาก https://ollama.com/download
3. เชื่อมต่ออินเทอร์เน็ตชั่วคราว แล้วดับเบิลคลิก `Open-PSU-Esports-Chatbot.cmd`
4. ครั้งแรกไฟล์นี้จะดาวน์โหลด Local Model และ RAG embedding model ให้อัตโนมัติ แล้วเปิดหน้าเว็บเอง

การดาวน์โหลดในข้อ 3 เป็นครั้งแรกครั้งเดียว หลังจากนั้นการตอบ Chatbot ใช้โมเดลในเครื่อง ไม่ใช่ Chatbot API ภายนอก

## วิธีเปิดใช้งาน

1. ดับเบิลคลิก `Open-PSU-Esports-Chatbot.cmd` เพียงไฟล์เดียว
2. ตัวเปิดเบื้องหลังเลือกพอร์ตว่างในช่วง `8090..8099` และตรวจทั้งรุ่นกับรหัสชุดก่อนใช้เว็บที่เปิดค้างอยู่ ดู URL จริงจากข้อความตอนเปิดและแถบข้อมูลบนหน้าเว็บ; ตัวเปิดแบบหน้าต่างใช้พอร์ต 8090 เป็นค่าเริ่มต้นและกำหนด `-Port` ได้
3. รอการตรวจความพร้อมและคำตอบทดลองผ่านก่อนเปิดเว็บ เมื่อใช้ตัวเปิดปกติหรือแบบ Background สามารถปิดหน้าต่างคำสั่งได้ ระบบยังรันเบื้องหลัง; ถ้าเรียก `Start-PSU-Esports-Chatbot.ps1` แบบ foreground โดยไม่ใช้ `-OpenBrowser` ต้องเก็บหน้าต่างนั้นไว้
4. เมื่อถามสถานะว่าง/ถูกจองหรือรอบที่จองได้ Chatbot จะดึง WordPress CSV สดให้เอง โดยใช้ตัวคำนวณ Slot และปฏิทินที่บันทึกไว้ของ Dashboard ไม่ต้องเปิด `start-dashboard.bat` สำหรับชุด Chatbot อย่างเดียว ถ้าเปิด Dashboard เจ้าของบน D: ที่พอร์ต 8080 ก่อน Chatbot จะอ่านจากตัวนั้นเพื่อคงปฏิทินที่เจ้าของแก้ไว้

ใช้ `Open-PSU-Esports-Background.cmd` เมื่อต้องการเลือกพอร์ตว่าง 8090..8099 อัตโนมัติ ระบบเก็บ log การเริ่มครั้งใหม่ไว้ใน `data\logs\launcher\` และดึง Booking เมื่อมีคำถามสถานะ หากเปิด Dashboard บน D: ก่อนจะอ่านจากพอร์ต 8080 วิธีนี้ยังไม่เริ่มเองหลังเข้าสู่ Windows; หากต้องการแบบนั้นให้ตั้ง Windows Task Scheduler บนเครื่องเจ้าของ

Dashboard ต้นฉบับที่เปิดด้วย `start-dashboard.bat` ใช้พอร์ต 8080 ถ้าเปิด **ก่อน Chatbot** ตัวเปิดจะเลือกข้อมูลจาก D: และลองอ่านข้อมูลใหม่เมื่อมีคำถามสถานะทุกครั้ง ไม่ปิดความสามารถนี้ถาวรเพราะอินเทอร์เน็ตล่มตอนเปิดระบบ หากไม่ได้เปิด D: ก่อน Chatbot จะดึง WordPress เองพร้อมใช้ปฏิทินของแพ็กเกจ ถ้าเปิด D: ภายหลัง ให้ปิดแล้วเปิด Chatbot ใหม่เพื่อสลับแหล่งสถานะ การแก้ตารางใน D: ไม่ถูกคัดลอกไปอีกชุดโดยอัตโนมัติ

ตัวอย่างคำถามสถานะ Slot แบบเจาะจง:

- `PC Zone ว่างอะไรบ้างช่วง 15:00-16:00`
- `PC2 ว่างไหม` หรือ `PC #02 ว่างไหม` (หากไม่ระบุวันและเวลา ระบบตรวจเวลาปัจจุบัน)
- `วันนี้ตอน10โมง PC1 ว่างไหม` (ตรวจ PC #01 เฉพาะช่วง 10:00-11:00)
- `PC3 ตอนบ่ายโมงว่างไหม` จะหมายถึง Slot `13:00-14:00`; รองรับ `บ่ายโมงครึ่ง`, `บ่ายสอง` และ `บ่ายโมงถึงบ่ายสองโมง`
- `PC3 พรุ่งนี้บ่ายโมงว่างไหม` สำหรับ Slot ล่วงหน้า และ `PC3 เมื่อวานบ่ายโมงเคยถูกจองไหม` สำหรับดูประวัติ
- `Cockpit ว่างให้เล่นไหม`, `PlayStation ว่างไหม`, `VR ว่างไหม`, `Nintendo Switch ว่างไหม`
- `PC กับ VR ว่างไหม` หรือ `Cockpit, PlayStation and Nintendo available?`
- `PC #02 ว่างไหม 13:00-14:00`
- `PS5 ว่างอะไรบ้างพรุ่งนี้ 13:00-14:00`
- `Which PS5 stations are free tomorrow from 13:00 to 14:00?`
- `Is PC2 free?` (checks the current time)
- `Is PC #02 free from 13:00 to 14:00?`

ช่วง 12:00-13:00 ไม่เปิดให้จอง และ VR ที่จอง 30 นาทีจะกันสิทธิ์เต็ม Slot ชั่วโมงนั้น เช่น 09:00-09:30 กัน 09:00-10:00
การตอบช่วงเวลา เช่น `13:00-14:00` จะนับว่าเครื่องว่างก็ต่อเมื่อว่างตลอดทั้งช่วงเท่านั้น
เมื่อถามช่วงเวลาที่ผ่านไปแล้ว ระบบจะรายงานจากประวัติ Slot ว่า `ถูกจอง` หรือ `ไม่มีรายการจอง` แทนการกล่าวว่า Slot นั้นยังจองได้ในปัจจุบัน
คำถามเครื่องเดียว เช่น `PC2 ว่างไหม`, `PS5 #01 ว่างไหม` หรือ `Cockpit #02 ว่างไหม` จะตอบเฉพาะเครื่องนั้น; คำถามโซน เช่น `PC Zone ว่างไหม`, `VR ว่างไหม` หรือ `Nintendo ว่างไหม` จะสรุปจำนวนว่างและสถานะรายเครื่องทั้งหมดในโซนนั้น หากถามหลายโซนในคำถามเดียว ระบบจะแยกคำตอบตามโซนที่ระบุ
4. เมื่อต้องการปิดระบบ ให้กด `Ctrl + C` ที่หน้าต่าง PowerShell นั้น

หน้าเว็บรองรับ Auto / ไทย / English และใช้ Semantic RAG กับ Local LLM เพื่อช่วยเข้าใจคำถามที่เขียนได้หลายรูปแบบ

## Session และประวัติสนทนา

- ทุกครั้งที่เปิดหรือ refresh หน้าเว็บ ระบบจะเริ่ม Session ใหม่และหน้าแชตจะแสดงว่าง
- ข้อความและคำตอบของทุก Session ถูกเก็บถาวรใน SQLite และ JSONL เพื่อให้ผู้ดูแลดูย้อนหลังได้ทั้งหมด
- ปุ่ม `ล้าง / Clear` เริ่ม Session ใหม่ แต่ไม่ลบ log เดิมของผู้ดูแล
- เปิด `View-Chat-Logs.cmd` เพื่อสร้างรายงานทุก Session และทุกประวัติการคุยใน browser

## ข้อมูลและความเป็นส่วนตัว

- ฐานความรู้, vector index, Local LLM และประวัติสนทนาอยู่ในเครื่องนี้
- Chat log จะอยู่ที่ `data\logs\` และ session history อยู่ใน `data\logs\chat_history.sqlite3`
- ระบบบันทึก Session ID, คำถาม, คำตอบ, เวลา, route, mode, latency, ภาษา และแหล่งอ้างอิงของแต่ละคำตอบ
- ห้ามส่งโฟลเดอร์ `data\logs\` ให้บุคคลอื่น เพราะอาจมีข้อความที่ผู้ใช้พิมพ์ไว้
- คำตอบความรู้ทั่วไปใช้ข้อมูล release ที่แพ็กมาด้วย; URL ท้ายคำตอบเป็นแหล่งอ้างอิง ไม่ใช่การดึงหน้าเว็บสดทุกครั้ง
- ข้อยกเว้นคือคำถามสถานะเปิด-ปิดหรือ Slot จอง: ระบบอ่าน WordPress CSV สดเมื่อมีคำถาม โดยใช้ตัวคำนวณเดิมของ Booking Dashboard หรืออ่านจาก Dashboard เจ้าของที่เลือกไว้ หากดึงไม่สำเร็จจะไม่อ้างว่ารู้สถานะสด

## การแก้ปัญหาเบื้องต้น

| อาการ | วิธีแก้ |

| เปิดเว็บไม่ได้ | ใช้ URL จริงที่ตัวเปิดแสดง ตรวจรุ่นบนหน้าเว็บ; หากใช้แบบหน้าต่าง ตรวจว่าหน้าต่าง Start ยังเปิดอยู่ |
| Port 8090 ถูกใช้งาน | ใช้ `Open-PSU-Esports-Background.cmd` ให้เลือกพอร์ตว่าง หรือเปิด `Start-PSU-Esports-Chatbot.ps1` ด้วย `-Port` อื่นที่ว่าง |
| คำตอบ Slot สดช้า/ตอบว่ายืนยันไม่ได้ | ตรวจอินเทอร์เน็ตและข้อความสาเหตุที่ตอบกลับ; ถ้าเปิด D: ก่อน Chatbot ให้ตรวจ Dashboard บนพอร์ต 8080 ด้วย; ระบบจะไม่เอาข้อมูลตัวอย่างหรือตารางเก่ามาอ้างว่าเป็นสถานะสด |
| คำตอบช้า | รอให้ Local Model warm up ในคำถามแรก และหลีกเลี่ยงการเปิดหลายหน้าต่างพร้อมกัน |

## ข้อควรรู้

- ชุดนี้ใช้ข้อมูล release ที่แพ็กมาด้วย ไม่อัปเดตข้อมูล WordPress/Facebook แบบ real-time
- การเพิ่มข้อมูลใหม่ต้องผ่าน workflow content/review แล้ว rebuild structured projection และ RAG index ก่อนแทนที่ชุดนี้
- Check Slot แบบอ่านอย่างเดียวรวมอยู่แล้ว: ตัวเชื่อมต่อ Booking อ่าน WordPress CSV สดแล้วตัดชื่อผู้จอง รหัสนัดหมาย อีเมล เบอร์โทร และ token ก่อนคำนวณสถานะ ส่งเข้าระบบตอบเฉพาะสถานะเปิด-ปิดและจำนวน Slot ว่าง/ถูกจอง ไม่บันทึก CSV ดิบลง log
- ชุดนี้ยังไม่สร้าง Booking, Hold Slot, ยกเลิกการจอง หรือยืนยันการจ่ายเงิน เพราะงานเหล่านี้ต้องใช้ WordPress write API และผู้ให้บริการชำระเงินจริงก่อน
- อ่านรายละเอียดการใช้งานและนโยบายข้อมูลที่ `LOCAL_OPERATION_AND_DATA_POLICY_TH.md` และขอบเขต feature ที่ `OWNER_HANDOFF_AND_SCOPE_TH.md`
# การตรวจความพร้อมก่อนเปิดเว็บ

ตัวเปิดจะเลือก Python ครั้งเดียวแล้วส่งตัวเดิมผ่านทุกขั้นตอน รองรับ `-PythonPath` หรือ `PSU_PYTHON_EXE` เพื่อระบุไฟล์โดยตรง และตรวจ Python 64-bit รุ่น 3.11 ขึ้นไป หากไม่ระบุ จะใช้ runtime ที่มากับชุดก่อน จากนั้นใช้ `python_runtime.path` ใน manifest แล้วจึงค้นจาก PATH เมื่อ path ที่ระบุไม่มีอยู่จะรายงานข้อผิดพลาด ไม่เปลี่ยนไปใช้ Python ตัวอื่นเงียบ ๆ ค่า manifest ที่เป็น absolute path ใช้ได้เฉพาะเครื่องที่มี path นั้น ส่วนชุดสำหรับแจกต้องมี bundled runtime หรือเลือก Python บนเครื่องปลายทาง

ก่อนเปิด browser หรือใช้เว็บของชุดเดียวกันซ้ำ จะตรวจรุ่นชุด ตำแหน่งติดตั้ง ตัว Python ผล warmup/preflight และ worker แล้วส่งคำถามทดลองเรื่องการจองล่วงหน้าที่มีคำตอบในข้อมูลต้นฉบับ ตรวจว่าตอบ **อย่างน้อย 1 ชั่วโมง** จริง HTTP 200 หรือ health ok อย่างเดียวไม่ถือว่าพร้อม ผลตรวจแต่ละครั้งอยู่ใน `data\logs\launcher\readiness_*.json` พร้อม stdout/stderr สำหรับ startup ใหม่ ถ้าเว็บเดิมไม่พร้อมจะบอกสาเหตุและเก็บ process เดิมไว้ให้ตรวจสอบ

คำถามทดลองใช้ Session ID ขึ้นต้น `startup-probe-` แยกจากบทสนทนาผู้ใช้ และบันทึกใน log ตามปกติ การตรวจนี้ยืนยันเพียงคำถามต้นฉบับหนึ่งข้อ ไม่รับรองทุกคำถาม ความว่างจองสด หรือโหลดหลายคนพร้อมกัน คอมพิวเตอร์และระบบที่รันเบื้องหลังต้องเปิดอยู่ระหว่างใช้
