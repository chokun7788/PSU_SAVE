## ขอบเขตของข้อสรุป

ผลด้านล่างเป็นการประเมิน **การเลือกเจตนาและตัวอย่างคำตอบ** ด้วยข้อความที่สร้างและติดป้ายด้วยมือ โดยปิด LLM/RAG fallback เพื่อหาสาเหตุในเส้นทางที่ทำซ้ำได้ ไม่ใช่อัตราความแม่นยำจากผู้ใช้จริง การวัดเวลาคือการเรียก pipeline ในเครื่องครั้งละคำถาม ไม่ใช่เวลา end-to-end ของหน้าเว็บหรือ WordPress คำถามจองสดในชุดนี้ตรวจเพียงว่าเลือกเส้นทาง `live_booking_status` และรักษา `PC1`/เวลาไว้; ยังไม่มี oracle ว่าช่วงนั้นว่างหรือถูกจองจริง

## ทำไม paper จึงสนับสนุนแนวทางนี้ แต่ไม่ใช่หลักฐานผลของ PSU

- [Misspelling Semantics in Thai](https://aclanthology.org/2022.lrec-1.24/) พบว่าการสะกดผิดโดยตั้งใจในภาษาไทยอาจสื่อความหมาย/อารมณ์ และการแก้สะกดทุกคำแบบไม่แยกบริบททำให้ผลเสียในงานที่ศึกษา จึงใช้การแก้เฉพาะวลีที่มีหลักฐาน ไม่ลบทุกตัวซ้ำทั่วข้อความ
- [LexToPlus](https://aclanthology.org/W13-4702/) ศึกษาข้อความไทยสื่อสังคมและการซ้ำอักษรท้ายคำโดยตั้งใจ จึงรองรับการทดลองยุบซ้ำเฉพาะ social utterance; paper ไม่ได้พิสูจน์ว่า regex ปัจจุบันถูกกับทุกข้อความ
- [Domain Adaptation of Thai Word Segmentation](https://aclanthology.org/2020.emnlp-main.315/) พบว่าการตัดคำไทยขึ้นกับโดเมน; วลี “มีไรเล่นมั่ง” ควรทดสอบในโดเมนศูนย์จริง ไม่ใช้ผลจากข้อความทางการแทน
- [On the Robustness of Intent Classification and Slot Labeling to Real-world Noise](https://aclanthology.org/2021.nlp4convai-1.7/) แสดงว่าความผิดรูปที่เจอจริงทำให้ทั้ง intent และ slot เสื่อม จึงวัด protected entity แยกจาก intent
- [Increasing Robustness for Cross-domain Dialogue Act Classification](https://aclanthology.org/2022.wnut-1.20/) พบว่าบริบทและรูปภาษาที่เปลี่ยนตามแพลตฟอร์มมีผลต่อ dialogue act; รองรับการแยกคำขอบคุณ/ลาเป็น act แต่ผล paper ไม่ได้เป็นคะแนนของแชทบอทนี้
- [Towards Interpreting and Mitigating Shortcut Learning Behavior of NLU Models](https://aclanthology.org/2021.naacl-main.71/) อธิบายความเสี่ยงของการพึ่ง feature คำที่เด่นแทนความหมายทั้งหมด; สำหรับโค้ดนี้สาเหตุเฉพาะพิสูจน์จากเงื่อนไข `"แข่ง"` และ QuestionFrame lock ไม่ใช่สรุปจาก paper อย่างเดียว

## การตรวจเพิ่มและสิ่งที่ยังไม่ยืนยัน

- `tests/test_thai_noisy_input_flow_20260929.py` กับ greeting test: 7/7 ผ่าน รวมตัวอย่างไม่ให้ social reply กลืนคำถามราคา และไม่ให้คำถาม catalog แข่งรถกลายเป็นกติกา
- surface input smoke และ competition priority smoke ผ่าน; unit tests เส้นทางคำตอบยืนยันและ protected intent อีก 40/40 ผ่าน
- แพ็กเกจใหม่ `owner_local_delivery_20260929_thai_noisy_r9/PSU_Esports_Chatbot_Local` สร้างใหม่ ไม่ทับ r8; ตรวจ `/health` บนพอร์ต 8093 ว่า version ใหม่และ warmup ผ่าน แล้วเรียก `/api/chat` กับคำทักทายผิด คำขอบคุณพิมพ์ซ้ำ ราคา PS5 ภาษาพูด รายการเกมภาษาพูด และ “เกมแข่งรด” ได้คำตอบที่คาด
- ยังไม่ได้ประเมินความแม่นยำกับข้อความผู้ใช้จริงตามที่เจ้าของเคยระบุว่ายังเก็บ ground truth จริงไม่ได้; ไม่ควรตีความ 49/49 หรือ 25/25 เป็นอัตราความแม่นยำใช้งานจริง
- ยังไม่ได้ยืนยันว่า `live_booking_status` คืน “ว่าง/ถูกจอง” ถูกต้องในทุกช่วง ด้วย fixture จาก WordPress ที่รู้ผลจริง ชุดนี้พิสูจน์เพียงการรักษาเวลา/หมายเลขเครื่องและการเข้าเส้นทางจอง
- ยังไม่ได้วัด latency เมื่อเปิด LLM และดึง WordPress จริงในชุด 74 คู่; ตัวเลข pipeline แบบปิด LLM ในรอบสุดท้ายคือ p50 0.2029 วินาที / p95 0.3221 วินาที สำหรับ 49 คู่ และ p50 0.2217 / p95 0.2935 วินาที สำหรับ holdout 25 คู่

## ลำดับต่อไปเมื่อมีหลักฐานจริง

1. รวบรวมข้อความผู้ใช้ที่ยินยอมให้ใช้ทดสอบ พร้อมป้าย intent, entity, และคำตอบที่ตรวจจากต้นทาง; แยกข้อมูลส่วนบุคคลออก
2. ทำ blind holdout ที่ผู้แก้โค้ดไม่เห็นก่อนแก้ แล้ววัดความผิดพลาดแยกตามรูปสะกดและหมวดคำถาม
3. ตรวจ fixture WordPress ที่ระบุเครื่อง/วัน/ช่วงเวลาและผลว่างหรือถูกจองจริงก่อนอ้างว่า booking status ถูก
4. แก้รูปคำตอบ “มีหูฟังไหม” ให้ตรงคำถาม ถ้าเจ้าของต้องการคำตอบสั้นแบบมี/ไม่มี พร้อมแหล่งอ้างอิง
