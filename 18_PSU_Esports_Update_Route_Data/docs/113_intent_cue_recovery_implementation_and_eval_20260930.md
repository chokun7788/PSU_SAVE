## ทดสอบแพ็กเกจผ่าน HTTP

เปิดแพ็กเกจ r18 ชั่วคราวที่ `127.0.0.1:8096` และปิดหลังทดสอบ; ตัวเดิมที่ `8095` ไม่ถูกแตะ ยิง 7 กรณีผ่าน `/api/chat` ได้ HTTP 200 ทั้งหมด เวลารวมฝั่ง client ต่อข้อ 0.047–2.962 วินาที คำตอบเรื่อง PUBG ราคา, PS5 ราคา+เกม, VALORANT Tab, temporary suspension และ play/pay ไปเส้นทางที่ตั้งใจ ส่วน 2 คำถามจองตอบว่าแหล่งข้อมูลสดไม่พร้อม เพราะการทดสอบนี้ปิด live booking ไว้ จึงตรวจได้เฉพาะการไม่เดาสถานะ ไม่ใช่ความถูกต้องของช่องจองจริง ผลเต็มอยู่ที่ `reports/typo_r16_20260930/api_spotcheck_r18.jsonl`

เวลา deterministic pipeline 4,000 calls: ค่าเฉลี่ย 0.381 วินาที, สูงสุด 15.150 วินาที, เกินเป้าใช้งาน 10 วินาที 3 calls, เกินเพดาน benchmark เดิม 20 วินาที 0 calls ค่านี้ไม่รวมความล่าช้าของ WordPress/Booking Dashboard หรือโมเดล LLM ซึ่งรอบนี้ไม่ได้เปิดทดสอบ (เครื่องทดสอบไม่มี Ollama listener ที่พอร์ต 11434)

## สิ่งที่ยังผิดหรือยังยืนยันไม่ได้

1. **คำพิมพ์ผิดที่ยังไม่กู้** — เหลือ legacy regression 181 ข้อ: โหมด `english_no_answer` 56, `no_answer` 29, `candidate_margin_clarification` 25 และกลุ่มอื่น ตัวอย่าง `Are drins allowwd` (ควรถาม/ตอบกฎเครื่องดื่มจากแหล่งยืนยัน), `สัปดาห์นี้มีวันปิิดพิเศษไหม` (ควรตรวจตาราง), `PC กับ VR อันไหนแพงกว่่า` (ควรไปเทียบราคา) ต้องทำ candidate หลายจุดพร้อมคะแนนและ guard ก่อนขยายคำศัพท์ทั่วไป เพราะคำจริงอย่าง `rice`/`price` อาจชนความหมาย
2. **ป้ายกำกับยังไม่รับรองโดยคน** — ใน 181 ข้อที่ยัง regression มี generated paraphrase pending review 72, inherited gold candidate 91, source-grounded gold candidate 18; ตัวเลขนี้เป็นผลเกณฑ์อัตโนมัติ ไม่ใช่จำนวนคำตอบผิดจริงที่เจ้าของตรวจแล้ว บางข้อ route ต่างแต่ตอบปฏิเสธอย่างปลอดภัย บางข้อ gold คาดคำตอบอังกฤษทั้งที่คำแปลกติกายังไม่อนุมัติ
3. **จองจริง** — fixture พิสูจน์ logic ว่าง/ถูกจอง/unknown ได้ แต่ยังไม่มีรายการวัน เวลา เครื่อง และสถานะจริงที่เจ้าของทราบแน่ตามที่พักไว้; HTTP 200 หรือ `remote_csv_live` เพียงอย่างเดียวพิสูจน์สถานะจริงไม่ได้
4. **แหล่งราคาและคำแปล** — ตัวตอบราคายังอ้างภาพ Jan 2026 ขณะที่หน้า booking มีภาพ Aug 2026; ยังไม่ยืนยันว่าตารางใดมีผลใช้จริง จึงไม่แก้ตัวเลข กติกาแข่งขันอังกฤษยังรอฉบับอนุมัติ และปุ่ม VALORANT อ้างคู่มือภายนอกที่ยังไม่ได้ตรวจบนเครื่องศูนย์
5. **การวัดในโหมดใช้งานจริง** — ยังไม่มีการวัด LLM เปิด, การเรียก Dashboard จริง, concurrent requests หรือ latency บนภาระงานเป้าหมาย แพ็กเกจนี้เป็นตัวทดลอง r18 ยังไม่ถือว่าผ่านเกณฑ์ใช้งานจริงทั้งหมด

งานวิศวกรรมในแผน v2 ที่ยังต้องทำต่อคือ trace คะแนน candidate/veto แบบตรวจย้อนกลับได้, holdout ที่คนตรวจและไม่ได้ใช้จูน, outcome/source coverage ต่อ task ในคำถามหลายเรื่อง, และ freshness/coverage ของ snapshot จองครบทุกกรณี การเพิ่มคำแก้สะกดทั่วไปก่อนมีชุดตรวจ false correction อาจทำให้คำจริงถูกเปลี่ยนเป็นเจตนาอื่น จึงหยุดขยายคำศัพท์ที่ยังไม่มีหลักฐานในรอบนี้

## คำถามที่ต้องให้เจ้าของศูนย์ตัดสินใจ

3. ปุ่มควบคุม VALORANT บนเครื่องที่ศูนย์ตรงกับคู่มือภายนอกหรือมี keybinding ที่เปลี่ยนไว้หรือไม่?
4. เมื่อพร้อมทดสอบจองจริง ขอวัน เวลา เครื่อง สถานะที่ทราบแน่ และเวลาที่ตรวจสถานะ เพื่อนำมาเทียบกับผล API แบบไม่เดา
