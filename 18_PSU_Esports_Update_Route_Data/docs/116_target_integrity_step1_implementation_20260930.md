# แก้ลำดับที่ 1: ป้องกันการตอบผิดเป้าหมาย — r19

วันที่ 30 กันยายน 2026 · ต่อจาก docs/114–115 · ดำเนินการตามคำขอให้ค่อย ๆ แก้ทีละลำดับ

## 1. สรุปสถานะ

แก้ข้อผิดที่มีหลักฐานชัด 3 กลุ่ม: คำเกริ่นพิมพ์ผิดทำให้ Sofa กลายเป็น TV, ตำแหน่งรองประธานพิมพ์ผิดกลายเป็นประธาน, และคำถามคนสร้างแชทบอทถูกตอบด้วยการแนะนำตัวบอท ทดสอบโค้ดรวมและแพ็กเกจ r19 แล้ว รายงานนี้ยืนยันเฉพาะขอบเขตที่ทดสอบ ไม่ใช่การปิดทุกปัญหาของระบบ

ข้อมูลสมาชิกและอุปกรณ์มี hash ตรงกับก่อนแก้ ไม่มีการแก้ราคา นโยบาย เวลาบริการ หรือข้อมูลเจ้าของเพื่อให้คะแนนผ่าน สำรองโค้ดสถานะก่อนเริ่มรอบนี้ ซึ่งรวมงาน r18 ที่ยังไม่ได้ commit ไว้ใน `reports/target_integrity_step1_20260930/before/` เก็บผลทุกครั้งไว้คนละไฟล์

## 2. สาเหตุและการแก้

| ปัญหา | สาเหตุเดิม | การแก้ | ขอบเขต |

ไฟล์แก้: `app/pipeline/structured_tools.py`, `app/pipeline/engine.py`, `app/pipeline/chatbot_identity.py` โดยรักษาการแก้ r18 ใน engine/preprocess ไว้

### เหตุผลของการถามกลับ

ผล `structured_members_role_clarification` ได้ความมั่นใจ 0.60 จึงต้องมีทางส่งคำถามกลับโดยตรง ตัว engine เดิมรับ structured answer ที่ความมั่นใจตั้งแต่ 0.82 เท่านั้น จึงทิ้งผลถามกลับและเลือกเส้นทางอื่นในรอบทดลองแรก แก้โดยรับโหมด clarification เฉพาะนี้ ไม่ลดเกณฑ์ความมั่นใจของคำตอบข้อเท็จจริงทั่วไป

การเลือกบทบาทเก็บ observed span, บทบาทที่เลือก, edit distance, status และทางเลือกที่เสมอกันใน evidence คะแนนนี้เป็นระยะความต่างของตัวอักษร ไม่ใช่ความน่าจะเป็นว่าคำตอบจริงถูกต้อง การระบุชื่อคนยังอาศัยข้อมูลสมาชิกเดิม

## 3. สิ่งที่พบระหว่างตรวจซ้ำ

รอบเปรียบเทียบแรกแก้ได้ 2 ข้อ แต่ทำให้ `ตำแหน่ง ประธาน ึือใคร` เสียใหม่ 1 ข้อ เพราะคำเชื่อมที่พิมพ์ผิดถูกต่อเข้าเป็นชื่อบทบาท แก้การแบ่งส่วนคำถามท้ายประโยคที่ลงท้ายด้วยใคร/คนไหน/คนใด เพิ่ม test กรณีนี้ แล้วรันชุดเดิมซ้ำ ผลสุดท้ายไม่มีข้อใหม่ที่แย่ลงในชุดที่ตรวจ

เก็บ `paired_affected_domains.jsonl` และ `paired_affected_domains_v2.jsonl` ไว้ด้วย ไม่ลบผลที่เคยพลาด ผลชี้ขาดใช้ `paired_affected_domains_final.jsonl` ซึ่งรันหลังแก้ creator lookup แล้ว

## 5. สิ่งที่ยืนยันแล้วกับสิ่งที่ยังไม่ได้ยืนยัน

**ยืนยันอัตโนมัติในขอบเขตนี้:** examples เป้าหมายถูก, role clarification ถูกส่งถึงคำตอบ, tests 71 ข้อผ่าน, ชุด 334 คู่ไม่มีข้อที่แย่ลง, API 8 ข้อผ่าน, source/package ตรง และไฟล์ข้อมูลสมาชิก/อุปกรณ์ 2 ไฟล์ไม่เปลี่ยน

**ยังไม่ได้ยืนยัน:** เจ้าของรับรองข้อมูลสมาชิก/อุปกรณ์ล่าสุด, ผลครบ 2,000 คู่บน r19, UI rendering, ผลกับ LLM ที่เปิดจริง, สถานะจองจาก WordPress จริง, ความครอบคลุมคำผิดนอกชุดที่ทดสอบ และ English role typo recovery แบบใหม่ รอบนี้ตรวจ English regression controls แต่ไม่ได้เพิ่ม role corrector ภาษาอังกฤษ

ไม่มีคำถามนโยบายที่ต้องให้เจ้าของตัดสินใจก่อนใช้การแก้ 3 จุดนี้ เพราะใช้ความสัมพันธ์และเป้าหมายจากข้อมูลเดิม อย่างไรก็ตามการรับรองว่าบุคคลยังดำรงตำแหน่ง ณ วันนี้ยังเป็นงานยืนยันข้อมูล ไม่ใช่สิ่งที่ tests พิสูจน์ได้

## 6. ลำดับต่อไป

1. แยก “มีเกม/อุปกรณ์อะไร” ออกจาก “ช่องจองว่างเวลานี้ไหม” ให้แน่นขึ้น โดยเฉพาะ `What gmes are available in Cockpit` ที่ถูกส่งไป live booking; ใช้ fixture ตรวจทั้งสองความหมาย ไม่ต้องรอเก็บข้อมูลจริง
2. ตรวจคำตอบหลายงานและเนื้อหาเฉพาะที่ผู้ใช้ถาม เช่น ราคา + เกม + วิธีจอง; แก้ positive contracts ควบคู่ ไม่วัดจาก route อย่างเดียว
3. ขยายการกู้คำผิดเฉพาะกลุ่มที่ยังหลุด พร้อม negative controls และหลักฐาน candidate/score; ห้ามซ่อมคำจริงที่กำกวมโดยอัตโนมัติ
4. รันชุดใหญ่หลังแต่ละการแก้ที่มีผลหลายหมวด และแยก evaluator change ออกจาก runtime change ตาม docs/112 และ docs/115

แพ็กเกจ r19 ใช้ทดสอบได้ด้วย `Open-PSU-Esports-Chatbot.cmd` ในโฟลเดอร์ใหม่ ต้องปิด server รุ่นเดิมด้วยวิธีปกติก่อนสลับรุ่นเพื่อไม่ให้หน้าเว็บกลับไปใช้ process เก่า รอบนี้ไม่ได้สลับ runtime ที่ผู้ใช้เปิดอยู่ให้อัตโนมัติ
