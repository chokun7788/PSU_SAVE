# กรอกข้อมูลให้แชทบอท: คู่มือพร้อมตัวอย่างทุกหมวด

## เปิดใช้งาน

ดับเบิลคลิก `Open-Owner-Content.cmd` ในโฟลเดอร์แพ็กเกจ แล้วเลือกหมวดทางซ้าย หน้ากรอกมีคำอธิบายและตัวอย่างให้ดูทันที

## ทำแค่ 4 ขั้นตอน

1. เลือกหมวด → กดเพิ่ม หรือเลือกข้อมูลเดิม
2. ช่องที่รู้จริงเลือก “มีข้อมูลยืนยัน” แล้วกรอก; ช่องที่ยังไม่รู้คง “ไม่ทราบ” เปิดดูตัวอย่างใต้ช่องได้
3. ตรวจข้อมูลจริง ติ๊กยืนยันแหล่งข้อมูล แล้วบันทึกร่าง; ตรวจทานและอนุมัติเมื่อพร้อม
4. เผยแพร่ให้แชทบอทอ่าน แล้วลองถามจากหน้าแชท คำถามใหม่จะอ่านฉบับใหม่

ร่างที่ยังไม่ครบสามารถบันทึกได้ แต่ช่อง ★ ต้องมีข้อมูลก่อนอนุมัติ/เผยแพร่ การอนุมัติและเผยแพร่ยังตรวจค่าจริงและรายการที่เชื่อมด้วย ไม่ใช่แค่เลือกสถานะครบ

ตัวอย่างทั้งหมดด้านล่างเป็นข้อมูลสมมุติเพื่ออธิบายการกรอก ไม่ใช่ประกาศ ราคา หรือกติกาจริงของ PSU ไม่ใส่ตัวอย่างลงฐานข้อมูลอัตโนมัติ

## ตัวอย่างงานที่ต้องใช้หลายหมวด

### เพิ่มเกมใหม่ให้ตอบได้ครบ

1. **เกม**: ใส่ชื่อ เนื้อหา และวิธีเล่น → เผยแพร่
2. **โซน → เครื่องจริง → ตัวเลือกบริการ**: สร้างเฉพาะรายการที่ยังไม่มี แล้วเผยแพร่ตามลำดับ
3. **เกมที่มีให้เล่นจริง**: เลือกเกมและบริการนั้น ระบุมี/ไม่มี และเครื่องเฉพาะถ้าทราบ
4. **ปุ่มควบคุมเกม**: เลือกเกม แพลตฟอร์ม อุปกรณ์ ชุดปุ่ม และเพิ่มปุ่มทีละรายการ
5. **การเล่นกับเพื่อน**: กรอกโหมดและจำนวนผู้เล่นที่ตรวจแล้ว หากอยากให้ตอบเรื่องเล่นหลายคน

กรอกแค่หมวดเกมจะให้ข้อมูลทั่วไปของเกม แต่ยังไม่ยืนยันว่าศูนย์ติดตั้งเกมหรือมีปุ่มควบคุมเกมนั้น

### เพิ่มราคาใหม่

สร้างหรือเลือก **กลุ่มผู้ใช้** และ **ตัวเลือกบริการ** ที่ตรงกัน → เผยแพร่รายการที่เชื่อมก่อน → เพิ่ม **ค่าบริการปกติ** พร้อมวันเริ่มมีผล หน่วยราคา จำนวนคน และวิธีคิดตามเอกสาร

หน้าเว็บช่องราคา **กรอกเป็นบาทได้เลย** เช่น 35 หรือ 35.50 ระบบแปลงเก็บเป็นสตางค์ให้อัตโนมัติ (JSON สำหรับผู้ดูแลยังเก็บ 35 บาท → 3500, 35.50 บาท → 3550, 4,000 บาท → 400000); ใส่ 0 เฉพาะเมื่อยืนยันว่าฟรี ระบบคำนวณราคาและปฏิทินบางเส้นทางยังใช้ตัวอ่านเดิมร่วมด้วย ต้องตรวจคำตอบจริงก่อนนำข้อมูลใหม่ไปใช้ทุกเส้นทาง

### เพิ่มกติกาแข่งขัน

เกม → รายการแข่งขัน (เกม/ชื่อ/ปี/ฉบับ) → ข้อกติกาทีละข้อ (เลขข้อ/หมวด/ข้อความเต็ม) หากมีข้อยกเว้นเชื่อมกันต้องเลือกข้อที่เกี่ยวข้องของรายการเดียวกัน

### เพิ่มเวลาเปิดหรือวันปิด

เวลาประจำสัปดาห์ = ตารางตามชื่อวัน; วันปิดพิเศษ = วันที่แน่นอน เวลาเปิดพื้นที่กับช่วงจองได้กรอกแยกกัน ตัวอย่าง 09:00–17:00 เปิดพื้นที่ แต่ช่วงจอง 09:00–12:00 และ 13:00–17:00 ไม่ได้ทำให้จองช่วง 12:00–13:00 ได้

## ตัวอย่างแต่ละหมวด

ตัวอย่างเป็นภาษาหน้ากรอก ไม่ต้องเขียน JSON หรือโค้ดเอง ราคาและวันที่ตัวอย่างไม่ใช่ข้อมูลจริงของศูนย์

### ข้อมูลพื้นฐานศูนย์

**ใช้เมื่อ:** เมื่อเพิ่มชื่อศูนย์ หน่วยงานเจ้าของ ที่อยู่ หรือแผนที่

**ช่วยตอบ:** ศูนย์อยู่ที่ไหน อยู่ตึกอะไร

**จำง่าย ๆ:** หนึ่งรายการต่อศูนย์ ไม่ใส่ราคาหรือสถานะจองในที่อยู่

**สร้างข้อมูลอื่นก่อนเฉพาะที่ใช้เชื่อม:** เริ่มหมวดนี้ได้เลย

| ช่องที่เห็นในหน้าเว็บ | ต้องมีก่อนเผยแพร่ไหม | ตัวอย่างการกรอก |
|---|---|---|
| ชื่อศูนย์อย่างเป็นทางการ | ★ ต้องมี | ภาษาไทย: ศูนย์อีสปอร์ตตัวอย่าง • ภาษาอังกฤษ (ยังไม่มีคำแปลให้เว้นว่าง): เว้นว่าง |
| หน่วยงานเจ้าของ/ผู้ดำเนินการ | ★ ต้องมี | ภาษาไทย: มหาวิทยาลัยตัวอย่าง • ภาษาอังกฤษ (ยังไม่มีคำแปลให้เว้นว่าง): เว้นว่าง |
| ศูนย์ทำอะไร/ขอบเขตบริการ | ยังไม่ทราบได้ | ภาษาไทย: พื้นที่ฝึกทักษะเกมและอีสปอร์ต • ภาษาอังกฤษ (ยังไม่มีคำแปลให้เว้นว่าง): เว้นว่าง |
| ที่อยู่เต็ม | ยังไม่ทราบได้ | ภาษาไทย: อาคารตัวอย่าง ชั้น 1 • ภาษาอังกฤษ (ยังไม่มีคำแปลให้เว้นว่าง): เว้นว่าง |
| อาคาร | ยังไม่ทราบได้ | อาคารตัวอย่าง |
| ชั้น | ยังไม่ทราบได้ | 1 |
| ลิงก์แผนที่ | ยังไม่ทราบได้ | https://example.com/info |
| เขตเวลา | ★ ต้องมี | เวลาไทย |

**วิธีใช้ตัวอย่าง:** เปิดช่องนี้ในหน้าเว็บ เลือก “มีข้อมูลยืนยัน” แล้วใส่ข้อมูลจริงของศูนย์แทนค่าตัวอย่าง หากยังไม่มีข้อมูลจริงให้คง “ไม่ทราบ” และบันทึกเป็นร่างไว้

**ช่วยตอบ:** PC #01 ตอนนี้ว่างไหม

**จำง่าย ๆ:** กรอกค่าจริงจากระบบ ไม่กรอกคำว่าว่างด้วยมือ การกรอกหมวดนี้ยังไม่เชื่อม API ใหม่ให้อัตโนมัติ

**สร้างข้อมูลอื่นก่อนเฉพาะที่ใช้เชื่อม:** ตัวเลือกบริการบนหน้าจอง / เครื่องจริง เช่น PC #01

| ช่องที่เห็นในหน้าเว็บ | ต้องมีก่อนเผยแพร่ไหม | ตัวอย่างการกรอก |
|---|---|---|
| เลือกตัวเลือกบริการบนหน้าจอง | ★ ต้องมี | เลือกชื่อจากหมวด ตัวเลือกบริการบนหน้าจอง ที่สร้างไว้ก่อน ไม่ต้องพิมพ์รหัส |
| ผู้ให้ข้อมูลสด | ★ ต้องมี | ระบบจอง WordPress |
| รหัสเครื่องหรือบริการที่ API ใช้จริง | ★ ต้องมี | รหัสจริงจาก API ห้ามเดา |
| รหัสเครื่องที่ใช้ร่วมกัน (คัดลอกจากระบบจริง) | ★ ต้องมี | pc_01 |
| ค่าจาก API แต่ละค่าหมายถึงอะไร | ★ ต้องมี | รายการ 1: ค่าดิบที่ API ส่งกลับ: ค่าจริงที่ API ส่งกลับ • ความหมายของสถานะ: ยังไม่ทราบ |
| เขตเวลา | ★ ต้องมี | เวลาไทย |
| ข้อมูลเก่าได้กี่วินาที ตามนโยบายที่อนุมัติ | ★ ต้องมี | ภาษาไทย: นโยบายอายุข้อมูลที่ผู้ดูแลอนุมัติ • ภาษาอังกฤษ (ยังไม่มีคำแปลให้เว้นว่าง): เว้นว่าง |

**วิธีใช้ตัวอย่าง:** เปิดช่องนี้ในหน้าเว็บ เลือก “มีข้อมูลยืนยัน” แล้วใส่ข้อมูลจริงของศูนย์แทนค่าตัวอย่าง หากยังไม่มีข้อมูลจริงให้คง “ไม่ทราบ” และบันทึกเป็นร่างไว้

## ข้อที่มักสับสน

- **ไม่ทราบ** = ยังไม่มีหลักฐาน; **ไม่เกี่ยวข้อง** = ยืนยันแล้วว่าช่องนี้ใช้ไม่ได้กับรายการนี้; **ไม่มี/ไม่รองรับ** = เลือกมีข้อมูลยืนยัน แล้วเลือก “ไม่ใช่ / ไม่มี / ไม่รองรับ”
- **รายการว่าง** = เลือกมีข้อมูลยืนยันแล้วไม่เพิ่มแถว ใช้เฉพาะช่องที่ความหมายอนุญาต เช่น ทุกโซนหรือไม่มีเงื่อนไข; ไม่ใช่การแทนค่าที่ไม่ทราบ
- **ชื่อเรียกอื่น** = ชื่อย่อที่ใช้จริง เช่น ชื่อย่อเกม ไม่ต้องสร้างรายการทุกคำพิมพ์ผิด
- **อังกฤษ** = ยังไม่มีก็เว้นว่าง ถ้ามีคำแปลเลือกแปลโดยระบบหรือเจ้าของตรวจแล้วตามจริง หากเลือกตรวจแล้วต้องติ๊กยืนยันฉบับนี้ด้วย
- **วันเริ่มมีผล** = ใช้วันที่ ค.ศ. และเวลาไทยตามประกาศจริง ไม่ใช้วันที่ตัวอย่างเป็นนโยบาย
- **ไม่พบชื่อในช่องเชื่อม** = สร้างและบันทึกหมวดต้นทางก่อน แล้วกลับมาโหลดรายการล่าสุด/เปิดรายการนี้ใหม่ รายการต้นทางต้องเผยแพร่ก่อนรายการที่อ้างถึง
- **บันทึกร่างแล้วแชทยังไม่เปลี่ยน** = ต้องอนุมัติและเผยแพร่ก่อน หน้า “ทดลองคำตอบ” อ่านเฉพาะฐานกลาง; สถานะจองสดและระบบรวมต้องลองหน้าแชท
- **สถานะว่าง** = อ่านจาก WordPress ตามเวลา ไม่กรอกด้วยมือในเครื่องจริงหรือ FAQ

## ก่อนใช้ข้อมูลจริง

ตรวจชื่อ/จำนวน/ราคา/วันที่จากเจ้าของ ไม่เติมข้อห้ามหรือเงื่อนไขใหม่โดยเดา ร่างเดิม 41 รายการยังต้องตรวจตามจริง การแสดงตัวอย่างช่วยกรอก ไม่ใช่การยืนยันข้อมูลเดิมแทนเจ้าของ
