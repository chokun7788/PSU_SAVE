# r23 — คำถามกว้างให้แสดงเฉพาะอุปกรณ์ที่ว่าง

วันที่ตรวจ: 2026-10-01 เวลาไทย

## คำขอและสาเหตุ

คำถามจริง: `ตอนบ่าย3มีอุปกรณ์อะไรว่างให้เล่นบ้าง`

ใน r22 คำถามนี้ถูกส่งไป `pipeline:structured_equipment_catalog` เพราะเงื่อนไขตรวจคำว่า `มีอุปกรณ์` / `what equipment` ตัดคำถามออกจากการตรวจสถานะจองก่อนพิจารณาคำว่า “ว่าง” และเวลา จึงตอบรายการอุปกรณ์บนหน้า Home แทนความว่างของ Slot

## สิ่งที่แก้และ Flow

แก้ `app/booking/live_status.py` และเพิ่ม `tests/test_available_equipment_only_20261001.py`

1. ตรวจว่าเป็นคำถามหาอุปกรณ์ว่างจากคำเรียกอุปกรณ์ ร่วมกับคำบอกความว่างและบริบทเวลา รองรับไทยและอังกฤษ
2. ถ้าถามรายการอุปกรณ์ทั่วไป เช่น `มีอุปกรณ์อะไรบ้าง` หรือ `What equipment is available?` โดยไม่มีบริบทความว่าง/เวลาที่ชัดเจน ให้ใช้รายการอุปกรณ์เดิม
3. คำถามความว่างดึงสถานะสดผ่านแหล่งที่ตัวเปิดระบบเลือกไว้ ไม่มีการใช้ตารางเก่าแทนสถานะสด
4. อ่าน `บ่าย3` / `บ่ายสาม` / `3pm` เป็น 15:00 และตรวจเต็ม Slot ที่ระบบจองส่งมา คือ 15:00–16:00 ในชุดที่ตรวจ
5. ถ้าถามช่วงหลาย Slot รายการต้องว่างครบช่วงและมีข้อมูลครอบคลุมครบจึงแสดง
6. คำถามกว้างแสดงเฉพาะรายการที่ยืนยันว่าว่าง จัดกลุ่มตามโซน พร้อมวัน เวลาอัปเดต และแหล่งข้อมูล
7. คำถามเฉพาะโซน เช่น `PC ว่างไหมตอนบ่าย3` ยังแสดงสถานะ PC ทุกเครื่องตามพฤติกรรมที่ผู้ใช้ขอไว้ก่อนหน้า
8. วันปิด / Maintenance ไม่แสดงรายการให้จอง ข้อมูลไม่ครบไม่ถือว่าว่าง ข้อมูลช่วงที่ผ่านไปแล้วระบุว่าเป็นประวัติ
9. ถ้าดึงข้อมูลไม่สำเร็จ แจ้งว่ายังยืนยันไม่ได้ และคำถามครั้งต่อไปดึงใหม่

## ผลทดสอบอัตโนมัติที่มีคำตอบจาก fixture

| ชุดทดสอบ | ผล |
| --- | --- |
| ชุดใหม่ r23 และ regression การจอง/ปฏิทิน/คำพิมพ์ผิด | 59 test methods ผ่าน |
| regression r21, intent trap และ service policy | 38 test methods ผ่าน |
| รวม | 97 test methods ผ่าน |

ชุดใหม่มี 11 methods ตรวจการเลือก 15:00 แทนสถานะปัจจุบัน การกรองเครื่องที่ถูกจอง การจองบางส่วน/no-show ข้อมูล Slot ขาด วันปิด ช่วงอดีต ไทย/อังกฤษ การคงคำตอบทุกเครื่องเมื่อถามโซน และกรณีข้อมูลสดใช้ไม่ได้

การรันแรก `tests_A.log` มี 3 failures เพราะ fixture ใหม่ยังใช้ Nintendo Slot 15:00 ที่ว่างจาก fixture เดิม แต่ assertion ตั้งใจตรวจกรณีถูกจอง จึงกำหนดสถานะนั้นให้ถูกจองในสำเนา fixture ใหม่ให้ตรงเงื่อนไขที่ตั้งใจทดสอบ ไม่ได้แก้ fixture เดิมหรือ Ground Truth เดิม ผลหลังแก้การตั้ง fixture เก็บใน `tests_B.log`

ผลนี้ยืนยันพฤติกรรมกับเงื่อนไขที่รู้ผลจาก fixture ไม่ใช่คะแนนความถูกต้องทั้งหมดของ chatbot และไม่ใช่การยืนยันรายการจองจริงโดยเจ้าของ

## ผลกับ API ที่เว็บแชทใช้จริง

ทดสอบก่อนเปลี่ยนเว็บบน port 8092: 6/6 cases ผ่าน ประกอบด้วยคำถามจริง บ่ายสาม ภาษาอังกฤษ คำถาม PC ทั้งโซน วันศุกร์ Maintenance และคำถามรายการอุปกรณ์ทั่วไป

หลังเปิด r23 บน port 8090: รอบ `http_final.json` ผ่าน 5/6 cases คำถามจริงครั้งแรกดึงข้อมูลเกิน timeout 5 วินาที จึงตอบว่ายังยืนยันไม่ได้ภายใน 5.7839 วินาที อีกห้าคำถามผ่าน ไม่ควรตีความ failure นี้ว่าไม่เข้าใจคำถาม เพราะ trace ระบุ `live_booking_status` และ error การดึงข้อมูล

ลองคำถามจริงซ้ำหนึ่งครั้ง: ผ่านทุกเงื่อนไข ใช้ 2.0543 วินาที ได้ `pipeline:live_booking_status_fast_path`, `source=remote_csv_live`, `transport=dashboard`, `cached=false`, เวลาอัปเดต 15:44:19 และแสดงเฉพาะ 7 รายการที่ API รายงานว่าว่างในช่วง 15:00–16:00 ผลทั้งครั้งที่ timeout และครั้งที่สำเร็จเก็บแยกกัน

เครื่องนี้มี Dashboard ต้นฉบับของเจ้าของบน port 8080 อยู่แล้ว ตัวเปิด r23 จึงเลือก Dashboard ตามวิธีเดิม หากไม่มี Dashboard ตอนเริ่มระบบ ตัวเปิดชุด r22/r23 รองรับดึง WordPress โดยตรง รายงานรอบนี้ไม่อ้างว่าได้ทดสอบความว่างจริงจากทั้งสองเส้นทางพร้อมกัน

## สิ่งที่ยังไม่ได้รับการยืนยันจากเจ้าของ

- ความว่างของรายการจริงยังไม่ได้เทียบกับคำตอบอิสระจากเจ้าของหรือผู้ดูแลหน้าจอง การเชื่อม API สำเร็จและผล fixture ผ่านเป็นหลักฐานคนละส่วน
- API มีรายการบริการแยกชื่อ Morning/Afternoon และ 30 Mins/1 Hour เช่น Nintendo และ VR รอบนี้แสดงชื่อรายการตาม API และนับเป็น “รายการ” ไม่ถือว่าแต่ละรายการเป็นอุปกรณ์คนละเครื่อง
- คำถามเจาะจงที่ต้องยืนยันก่อนรวมรายการเป็นจำนวนเครื่อง: Nintendo Morning/Afternoon ใช้เครื่องเดียวกันหรือไม่, VR 30 Mins/1 Hour ใช้อุปกรณ์ชุดเดียวกันหรือไม่, เมื่อจองหนึ่งรายการต้องกันรายการอื่นของเครื่องเดียวกันอย่างไร, ชื่อ Morning/Afternoon จำกัดเวลาที่เล่นจริงหรือเป็นชื่อแพ็กเกจ/บริการ
- มีความล่าช้าจากการดึงสถานะหนึ่งครั้งในรอบตรวจสุดท้าย ครั้งต่อไปดึงสำเร็จ หลักฐานนี้ยังไม่เพียงพอที่จะระบุสาเหตุภายใน Dashboard/WordPress หรือรับประกันเวลาตอบทุกครั้ง
