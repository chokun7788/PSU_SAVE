# การใช้งานจริงแบบ Local และข้อมูลสนทนา

## รูปแบบการใช้งานของชุดนี้

ชุดนี้ทำงานบนเครื่องเดียวและเปิดเว็บที่ `http://127.0.0.1:8080/` เท่านั้น จึงเหมาะสำหรับเจ้าของระบบหรือผู้ทดสอบที่ใช้งานบนเครื่องนั้น ไม่เปิดรับผู้ใช้จากอินเทอร์เน็ตหรือเครือข่ายภายในองค์กร

เมื่อเปิด Chatbot ระบบจะเริ่ม Booking Dashboard แบบ loopback ที่ `http://127.0.0.1:8091/` ด้วย เพื่อให้ตอบสถานะเปิด-ปิดและความว่างของ Slot แบบอ่านอย่างเดียวได้

Local LLM, RAG index, SQLite และ log ทั้งหมดอยู่ในโฟลเดอร์นี้ ไม่มี Cloud Chatbot API ในเส้นทางตอบคำถาม

## Session และการรีเฟรชหน้า

- เมื่อเริ่มเปิดหน้าเว็บ ระบบจะสร้าง Session ID ใหม่แบบสุ่มสำหรับบทสนทนานั้น
- เมื่อกด refresh, ปิดแท็บ หรือเปิดหน้าเว็บใหม่ หน้าเว็บจะเริ่ม Session ใหม่และแสดงบทสนทนาว่างตามเจตนา
- Log ของทุก Session เดิมยังอยู่ใน SQLite และ JSONL ต่อเนื่อง ไม่ถูกลบจากการ refresh หรือ Clear
- ในรายงานผู้ดูแล ระบบแสดง `Session #1`, `Session #2` ต่อเนื่องเพื่อให้อ่านง่าย พร้อม Session ID แบบสุ่มภายใน
- ปุ่ม `ล้าง / Clear` เริ่ม Session ใหม่ในหน้าเดิม และเก็บ audit log ของ Session ก่อนหน้าไว้

## ข้อมูลที่ระบบบันทึก

ต่อหนึ่งรอบคำถาม-คำตอบ ระบบบันทึก Session Number, Session ID, Message ID, Request/Exchange ID, เวลา, ข้อความผู้ใช้, คำตอบ, ภาษา, route, mode, ความเชื่อมั่น, เวลาใช้ตอบ, แหล่งอ้างอิง และสถานะข้อผิดพลาดถ้ามี

ไฟล์ที่เกิดขึ้นจริง:

- `data\logs\chat_history.sqlite3`: ฐานข้อมูล transcript และ session
- `data\logs\web_chat_YYYY-MM-DD.jsonl`: event log รายวันสำหรับตรวจสอบเชิงเทคนิค
- `data\logs\chat_history_report.html`: รายงานที่สร้างเมื่อเปิด `View-Chat-Logs.cmd`

## ข้อมูล Slot สดและความเป็นส่วนตัว

- Chatbot เรียกเฉพาะ `/api/chatbot-status` ของ Dashboard ไม่เรียก `/api/status` หรือ `/api/raw-check`
- Payload สำหรับ Chatbot มีเฉพาะชื่อทรัพยากร เวลา Slot และจำนวนว่าง/ถูกจอง ไม่มีชื่อผู้จอง รหัสนัดหมาย อีเมล เบอร์โทร หรือ token
- Dashboard ต้องยืนยัน `source=remote_csv_live` ก่อน Chatbot จะกล่าวว่าเป็นข้อมูลสด หาก Dashboard ใช้ sample fallback หรือเชื่อมต่อไม่ได้ Chatbot จะตอบว่ายืนยันสถานะสดไม่ได้
- ใช้ cache ภายในสูงสุด 10 วินาทีเพื่อลดการดาวน์โหลด WordPress CSV ซ้ำ; คำตอบจะแสดงเวลาอัปเดตและบอกเมื่อใช้ cache ระยะสั้น
- ความสามารถนี้เป็น read-only เท่านั้น ไม่สร้าง/แก้ไข/ยกเลิก Booking และไม่ยืนยันการชำระเงิน
- รองรับการกรอง `PC Zone`, `PlayStation 5/PS5 Zone`, `Nintendo Switch Zone`, `VR Zone` และ `Cockpit Zone`; สำหรับ PC, PS5 และ Cockpit สามารถระบุหมายเลขเครื่อง เช่น `PC #02` ได้
- เมื่อถามเป็นช่วงเวลา ระบบต้องพบว่าเครื่องว่างครอบคลุมทั้งช่วง เช่น `13:00-15:00`; หากถูกจองเพียงส่วนหนึ่ง จะไม่ตอบว่าเครื่องนั้นว่างตลอดช่วง

## วิธีเปิดดู Log

1. ปิดหน้าเว็บหรือปล่อยให้ระบบทำงานได้ตามปกติ
2. ดับเบิลคลิก `View-Chat-Logs.cmd`
3. Browser จะเปิดรายงาน HTML ที่จัดกลุ่มตามทุก Session ย้อนหลัง และมีข้อความเต็มของบทสนทนา

ค่าเริ่มต้นของรายงานคือทุก Session และทุกข้อความที่เคยเก็บไว้ หากฐานข้อมูลมีขนาดใหญ่มาก สามารถระบุจำนวนที่ต้องการเปิดได้ เช่น `./View-Chat-Logs.ps1 -SessionLimit 100 -MessageLimit 1000`

รายงานนี้เป็นข้อมูลลับ เพราะผู้ใช้อาจพิมพ์ข้อมูลส่วนบุคคลลงในแชต ห้ามส่งฐานข้อมูลหรือรายงานออกนอกผู้ดูแลที่ได้รับอนุญาต

## การสำรองและการเก็บรักษา

- สำรองเฉพาะ `data\logs\chat_history.sqlite3` ขณะปิดระบบแล้ว เพื่อหลีกเลี่ยงการคัดลอกระหว่างมีการเขียนข้อมูล
- ชุดนี้ยังไม่ลบประวัติอัตโนมัติ ผู้ดูแลต้องกำหนดระยะเวลาเก็บข้อมูลกับหน่วยงานก่อนเปิดบริการจริง
- หากต้องล้างประวัติทั้งหมด ให้หยุดระบบก่อนและย้าย `data\logs\chat_history.sqlite3` ไปเก็บในที่ปลอดภัย ไม่ควรลบทิ้งโดยไม่มีนโยบายอนุมัติ

## ข้อจำกัดด้านความปลอดภัย

ชุด Local นี้ไม่มีระบบ Login เพราะ bind ไว้ที่ `127.0.0.1` และออกแบบให้เจ้าของเครื่องใช้เองเท่านั้น หากจะเปิดให้เครื่องอื่นหรือสาธารณะใช้ ต้องเปลี่ยนเป็น production deployment ที่มี HTTPS, Login, server-side session, Postgres, retention policy, rate limit และสิทธิ์ดู log แยกตามบทบาทก่อน
