# Flow ย้ายข้อมูลเดิมเข้า Format กลาง — R63

## ขอบเขต
นำข้อมูลบริการเดิมเข้า schema studio-content-3.0 เป็นร่าง โดยเก็บต้นฉบับและฐานข้อมูลเดิมไว้ ไม่เผยแพร่ ไม่อนุมัติ ไม่เปลี่ยนราคา/นโยบาย/WordPress และไม่ใช้ log หรือ Ground Truth เป็นข้อเท็จจริง

1. อ่านข้อมูลจากโปรเจกต์จริงและสำรอง SQLite ด้วย backup API ซึ่งรวมข้อมูลใน WAL
2. เก็บไฟล์ต้นฉบับแบบ byte-for-byte พร้อม SHA256 และตารางการแปลงแต่ละช่อง
3. ย้ายรายการที่มีโครงสร้างไปหมวดตรงกัน เช่น game, person, equipment_model, service, game_service, rental_package, competition_rule
4. ข้อความที่มีแต่คำตอบเก็บเป็น FAQ พร้อมข้อความเต็ม ไม่เดา decision/เงื่อนไขหรือขั้นตอนย่อย
5. เก็บชื่อและ ID เดิมเมื่อหมวดตรงกัน เพิ่มช่องที่ขาดในฐานสำเนา; ถ้าร่างเดิมมีค่าต่างกัน ให้เก็บค่าร่างเดิมและแจ้งความต่าง ห้ามทับ
6. ระยะเวลาใช้จริงกับเวลาที่กินช่องจองเป็นคนละช่อง ถ้าไม่มีหลักฐาน occupancy ให้ unknown
7. บันทึกช่วงราคาเก่าที่มีวันหมดอายุ; ราคาเหมาที่ไม่มีวันเริ่มให้ validity unknown; ห้ามใช้วันที่รับไฟล์แทนวันที่ราคาเริ่มใช้
8. ความต่างของตาราง Dashboard และ service_calendar เก็บเป็น conflicted พร้อมหลักฐานทั้งสองฝั่ง
9. ปุ่มเกมที่ไม่มี gesture/context ชัดเจนเก็บข้อความเต็มใน limitations และคง bindings unknown ไม่สมมุติว่าเป็น press ทุกปุ่ม
10. ตรวจ schema, FK, evidence pointer, ค่าเงิน ×100, จำนวนเกม/เครื่อง/หัวข้อกติกา และการเก็บภาษาเดิมครบทุกแถว
11. ทดลองถามเฉพาะร่างในฐานสำเนา แยกผลการย้ายข้อมูลจากผลการเลือกคำตอบ; ข้อที่ตอบไม่ได้ต้องบันทึก ไม่ลบเคสออกจากคะแนน
12. ส่งฐานร่างและตัวเปิดหน้ากรอกแยกจากระบบเดิม พร้อมรายการสิ่งที่ต้องเติม/ตรวจ โดยไม่แก้แพ็กเกจ ZIP เดิม

## เกณฑ์สำเร็จของรอบนี้
ไฟล์ต้นฉบับไม่เปลี่ยน, ฐานเดิมและทุก revision อยู่ครบ, ฐานสำเนามีรายการกลางที่ตรวจ schema ได้, มีคำอธิบายช่องที่ยังแปลงไม่ได้, active release เดิมไม่เปลี่ยน และไม่มีการอนุมัติข้อเท็จจริงแทนเจ้าของ
