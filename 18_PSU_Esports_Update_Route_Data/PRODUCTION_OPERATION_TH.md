# ใช้งานจริงและอัปเดตข้อมูล — r62

## สิ่งที่ชุดนี้ทำ

เป็นเว็บแชทที่รันบน Windows 64-bit ในเครื่องที่เปิดระบบ และหน้าเจ้าของสำหรับกรอกข้อมูล 24 หมวด ทั้งสองหน้าใช้ฐานข้อมูลเดียวกันโดยค่าเริ่มต้น แบบ With Models รวมโมเดลแล้ว; แบบ Download Models รวมตัวรันแล้วแต่ต้องดาวน์โหลดโมเดลครั้งแรก

เมื่อเจ้าของเผยแพร่ข้อมูล แชทอ่านรุ่นที่เผยแพร่ในคำถามถัดไป ข้อมูลใหม่ใช้ schema ของหมวดและความสัมพันธ์ที่กรอก ไม่ต้องเพิ่มเงื่อนไขชื่อเกมในโค้ด การเข้าใจข้อความที่กำกวมมากยังอาจถามกลับ ไม่รับรองทุกประโยคที่เป็นไปได้

## เปิดและดูแล

1. แตกไฟล์ลงโฟลเดอร์ที่เขียนได้ หลีกเลี่ยงโฟลเดอร์ที่ยาวมากหรือกำลัง sync ระหว่างรัน
2. ดับเบิลคลิก Open-PSU-Esports-Background.cmd รอเตรียมโมเดลและตรวจ readiness ครั้งแรกบนเครื่องใหม่อาจใช้หลายนาที; เวลานี้แยกจากเวลาตอบคำถามเมื่อพร้อม
3. ถ้าเป็นแบบ Download Models ให้เปิด Setup-Local-Models.cmd ให้จบก่อนเปิดแชทหรือหน้าผู้ดูแล
4. ดับเบิลคลิก Open-Owner-Content.cmd สำหรับข้อมูล เจ้าของเปิดจาก launcher เพื่อรับสิทธิ์เฉพาะบัญชี Windows
4. ปิดแท็บเว็บได้ แต่เครื่องที่ให้บริการต้องเปิดอยู่ แหล่งจองสดต้องเข้าถึงอินเทอร์เน็ตได้
5. ถ้าข้อมูลไม่เข้าแชท ตรวจว่ากดเผยแพร่แล้ว เปิดแชทจากโฟลเดอร์เดียวกัน และไม่ได้กำหนด PSU_KNOWLEDGE_DB ให้ชี้อีกฐาน
6. หากระบบเดิมเปิดอยู่ launcher ใช้ version และ fingerprint ของ source ตรวจชุดที่กำลังรัน เลือกพอร์ตว่างสำหรับชุดใหม่โดยเก็บ process อื่นไว้
7. เก็บ data/knowledge/approved.sqlite และไฟล์ข้อมูลเจ้าของเป็นหลัก ใช้ SQLite backup เมื่อระบบยังทำงาน ห้ามคัดลอกเฉพาะ .sqlite ขณะที่มี WAL แล้วถือว่าสำเนาครบ
8. ก่อนอัปเดตโปรแกรม สำรองข้อมูลและ log ห้ามแทนที่ data/knowledge ด้วยฐานตัวอย่างหรือฐานจากเครื่องนักพัฒนา

## เพิ่มรายการใหม่ — ตัวอย่างสมมุติ ไม่ใช่ข้อมูลศูนย์

เพิ่ม “เกมผจญภัยทะเล” ในหมวดข้อมูลเกม:

- รหัสรายการถูกสร้างให้อัตโนมัติ ตั้งครั้งเดียวและเก็บไว้เมื่อแก้รายการเดิม
- ชื่อไทย/อังกฤษเป็นชื่อที่แชทใช้ตอบ ไม่จำเป็นต้องเหมือนรหัส
- กรอกแนวเกม เรื่องย่อ วิธีเล่น แพลตฟอร์ม เรตอายุเท่าที่มีหลักฐาน ช่องไม่ทราบใช้ “ยังไม่มีข้อมูลยืนยัน”
- เพิ่มโหมดเกมเพื่อยืนยันจำนวนผู้เล่น; เพิ่มเกมกับบริการเพื่อยืนยันว่าศูนย์มีเกมนี้บนบริการหรือเครื่องไหน; เพิ่มวิธีเล่นและปุ่มตามแพลตฟอร์ม
- บันทึกร่าง → ติ๊กทดสอบร่าง → ถามชื่อเกมกับหัวข้อที่ต้องการ → ตรวจข้อมูล → อนุมัติ → เผยแพร่
- รายการที่อ้างอิงต้องเผยแพร่ก่อน เช่น เครื่อง → บริการ → เกมกับบริการ การเลือกหลายรายการเผยแพร่ร่วมกันทำได้ผ่าน API ที่ตรวจความสัมพันธ์ทั้งชุด
- ในแชทจริงลอง “เกมผจญภัยทะเลเล่นยังไง” → “แล้วปุ่มล่ะ” → “ขอทั้งหมด” ตรวจว่าทุกส่วนมาจากรายการและแพลตฟอร์มที่ต้องการ

## แก้รายการเดิม

ค้นรายการ → เปิดแก้ → ใช้รหัสเดิม → เปลี่ยนเฉพาะค่าที่มีหลักฐาน → ดูความแตกต่าง → บันทึกฉบับใหม่ → ทดสอบร่าง → ตรวจและอนุมัติ → เผยแพร่

ราคาเก็บจำนวนเงิน หน่วย ระยะเวลา กลุ่มผู้ใช้ บริการ จำนวนคน และวิธีคำนวณแยกกัน อย่าเปลี่ยนราคาอย่างเดียวเมื่อหน่วยหรือกลุ่มเปลี่ยน แชทไม่ขยายราคาคงที่เป็นหลายชั่วโมงเอง ถ้าถามงบหลายคนโดยยังไม่ยืนยันหน่วย จะระบุว่ายังสรุปราคาทั้งกลุ่มไม่ได้

ร่างใหม่ยังไม่ทับฉบับที่ลูกค้าเห็น การถอนเก็บประวัติไว้และหยุดใช้ข้อมูลนั้น ชื่อเดิมที่เคยเผยแพร่ยังใช้ตามหารายการที่เปลี่ยนชื่อได้ แต่ไม่ทำให้ข้อเท็จจริงฉบับเก่ากลับมา

ข้อมูลที่เริ่มในอนาคตบันทึกร่างไว้ก่อน แล้วเผยแพร่เมื่อถึงเวลา ระบบนี้ยังไม่ตั้งเวลาเผยแพร่อัตโนมัติ และไม่ย้อนไปใช้ราคาเก่าที่ถูกถอนเพื่อเติมคำตอบ

## ข้อมูลที่ยังรอตรวจจริง

ฐานกลางที่ส่งต่อมีร่างเดิม 41 รายการ ยังไม่มี release กลางที่เจ้าของอนุมัติทั้งหมด ข้อมูลเดิมยังตอบผ่านเส้นทางเดิม ร่างเหล่านี้ต้องตรวจช่องจำเป็น แหล่งยืนยัน วันที่มีผล และสถานะคำแปลก่อนเผยแพร่ ดูรายการเจาะจงใน OWNER_REVIEW_PENDING.md

## ให้ลูกค้าใช้ผ่านอินเทอร์เน็ต

ชุดนี้เปิด 127.0.0.1 เพื่อใช้ในเครื่อง ไม่ใช่ URL สาธารณะและไม่ใช่ระบบที่เปิดบนมือถือของลูกค้าได้จากลิงก์เดียวทันที หากต้องการเว็บสาธารณะต้องกำหนด host/domain, reverse proxy HTTPS, rate limits, session isolation, สำรองข้อมูล และทดสอบโหลดบนเครื่องนั้นก่อน เจ้าของ editor ต้องอยู่หลังสิทธิ์ผู้ดูแล; ห้ามเปลี่ยน bind ของ owner editor เป็น 0.0.0.0 เพื่อแก้ปัญหานี้

การเก็บ log ใช้ session และคำถามที่ผู้ใช้ส่งมา ผู้ดูแลต้องกำหนดอายุเก็บและสิทธิ์เข้าถึงตามการใช้งานจริง ไม่มีการส่งประวัติแชทจากเครื่องพัฒนารวมกับแพ็กเกจ

## อังกฤษสำหรับข้อมูลใหม่

กรอกไทย → กดช่วยแปลไทยเป็นอังกฤษ (ร่าง) → ตรวจคำแปล → บันทึก → อนุมัติ → เผยแพร่ ปุ่มนี้แปลเฉพาะช่องข้อความไทย/อังกฤษตาม schema และไม่บันทึกเอง ตัวเลข วันที่ ลิงก์ และรหัสไม่ได้ให้โมเดลเปลี่ยน หากยังไม่ได้ตรวจความหมาย คงสถานะแปลโดยระบบ ไม่ใช้ผลทดสอบภาษาอังกฤษเดิมเป็นการรับรองข้อความใหม่ทุกฉบับ

## ตารางจองต้นทางกับข้อมูลกลาง

การแก้ราคา เวลา หรือวันปิดในฐานความรู้ ไม่ใช่การเขียนแก้ WordPress หรือยกเลิกการจองของลูกค้า เมื่อเปลี่ยนการให้บริการจริง เจ้าของต้องปรับระบบจองต้นทางให้ตรงกันด้วย ส่วน live_binding ในฟอร์มเป็นข้อมูลการเชื่อม ไม่ได้สร้าง adapter สำหรับ API ใหม่อัตโนมัติ แพ็กเกจนี้ยังไม่ได้รับรองการซิงก์ตารางกลางที่แก้ใหม่เข้ากับทุกหน้า WordPress
