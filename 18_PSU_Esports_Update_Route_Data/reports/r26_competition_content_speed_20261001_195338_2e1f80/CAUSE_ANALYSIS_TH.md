# วิเคราะห์สาเหตุและการแก้ r26 — คำตอบกติกาการแข่งขัน

## 1. ปัญหาคำตอบไม่ครบ แม้แหล่งข้อมูลถูก
คำถาม “กติกา VALORANT มีบทลงโทษประเภทไหนบ้าง” ได้ประโยคแรกเป็นหัวข้อ “ประเภทบทลงโทษในเกม” และรายละเอียดเพียง Round Loss / Map Forfeit ทั้งที่ s11–s15 มีครบ 5 ประเภท

สาเหตุมีหลายขั้น: ตัวค้นคืนได้ 5 hits แต่ renderer เลือกเพียง 3 แถว; หัวข้อที่ซ้ำคำถามได้คะแนนดีกว่าเนื้อหาย่อย; การตรวจคำตอบยืนยันเกมและ facet ของแหล่งข้อมูล แต่ไม่ได้บังคับให้รายการที่ถามต้องครบ จึงผ่าน validation ด้วย confidence 0.84 ตัวเลขนี้เป็นคะแนนตัดสินเส้นทางจาก retrieval และมีเพดาน ไม่ใช่ความน่าจะเป็นว่าทุกข้อในคำตอบถูกหรือครบ

แก้โดยอ่านรายการลำดับจากเอกสารเดียวกันที่มีหัวข้อและข้อครบทั้ง 5 เท่านั้น พร้อมแสดงเงื่อนไขเต็มและ source IDs s11–s15 ไม่เรียกรายการทั่วไปไปตอบความผิดเฉพาะ เช่น โกงหรือใช้ช่องโหว่

คำตอบที่ควรได้:
- Warning: ความผิดครั้งแรกที่มีผลกระทบต่ำ
- Round Rollback: ช่องโหว่กระทบรอบอย่างชัดเจน แต่ระบุเจตนาไม่ได้
- Round Loss: ตั้งใจใช้ช่องโหว่สร้างความได้เปรียบ
- Map Forfeit: ความผิดร้ายแรงหรือซ้ำที่กระทบผลของแผนที่
- Match Forfeit: cheating หรือ match fixing

## 2. พิมพ์ task word ผิด แล้วหลุดหมวด/หัวข้อ
“Tekken 8 tournamment format” กลายเป็นคำอธิบายเกมทั่วไป; “tablet/iPad in the RoV tournamment” กลายเป็นย่อหน้ากฎที่มี Global Ban และการเชื่อมต่อ ข้อห้าม iPad ไม่อยู่ในคำตอบ

ตัวแก้ task word เดิมต้องมีคำกติกาหรือ tournament ที่สะกดตรงเพื่อเปิดบริบท จึงแก้คำ tournament ที่เป็นสัญญาณเดียวไม่ได้ นี่คือการพึ่งคำสะกดตรงก่อนจะเปิดการแก้คำผิด

แก้ด้วย edit distance 1 ของคำยาว tournament เมื่อชื่อเกมใน registry มีอยู่แล้ว เก็บ raw input ไม่แก้ชื่อเกม/เลข ไม่แก้คำอังกฤษจริงที่ระบบกันไว้ ไม่บันทึก typo alias ทีละคำ ทดสอบ insertion/deletion/transposition และ negative controls ที่ไม่มีเกม/เกมไม่รองรับ

## 3. มีคำตอบจริงอยู่ท้ายข้อความ แต่ประโยคแรกตอบผิดหัวข้อ
หลังแก้ spelling คำถาม “tournament format” ยังได้ประโยคแรก “PlayStation 5 console used” เพราะ taxonomy รู้จัก competition format แต่ไม่มี tournament format ทำให้ facet ว่างและอ่าน clause แรกจาก source window ทั่วไป

ภาษาไทยถามรูปแบบการแข่งขันได้ประโยคแรกเป็นเพียงหัวข้อ “รูปแบบการแข่งขัน:” ตัวตรวจเดิมเห็น FT2 ในรายละเอียดจึงให้ผ่าน นี่ต่างจากการตอบตรงคำถามตั้งแต่ประโยคแรก

เพิ่มคำศัพท์ความหมาย tournament format ใน taxonomy ร่วม; จัดให้ไทยเริ่มด้วย clause 1v1/FT2 ที่ตรง facet แล้วรักษาค่า R3 / 60S ที่อยู่ในส่วนรูปแบบเดียวกัน เกณฑ์ใหม่บังคับประโยคแรกมี 1v1 หรือ FT2 แยกจากการตรวจว่าคำตอบทั้งหมดมี FT2 และ 2 เกม

รอบที่ลองตัดรายละเอียดให้เหลือแต่ format ทำให้ regression เดิมที่ต้องมี 60 วินาทีไม่ผ่าน จึงคืนค่ารอบ/เวลาในส่วนเดียวกันก่อนรับรุ่นสุดท้าย ไม่แก้ Gold หรือเงื่อนไขทดสอบเดิมเพื่อให้ผ่าน

## 4. รู้หัวข้อกว้าง แต่ไม่มีรายละเอียดเฉพาะ
ถาม minimum age ของ Tekken 8 แล้วระบบใช้ข้อความ “ต้องยอมรับกติกาและคำตัดสิน” มาตอบ เพราะ eligibility เป็นหัวข้อเดียวกัน แต่ข้อความนั้นไม่ได้ยืนยันอายุ

แก้ shared evidence guard ให้คำถามอายุขั้นต่ำต้องมี clause อายุพร้อมค่าและหน่วยจริง หมายเลขข้อ / ปี Update ไม่ถือเป็นหลักฐานอายุ ถ้าไม่พบให้ no_answer ทั้งไทยและอังกฤษ คำตอบที่ควรได้คือยังไม่มีข้อกฎยืนยันเรื่องอายุในเอกสารที่บันทึกไว้

ถามระยะเวลา VALORANT Technical Pause: เอกสารที่ตรวจมีข้อห้ามสื่อสารและข้อยกเว้น แต่ไม่มีระยะเวลาที่ถาม จึงต้องตอบไม่พบข้อกฎและห้ามยืม 60 วินาทีของ Tactical หรือ 10 นาทีของ Emergency

รอบแรกแก้ mode แต่ใช้ public hits ซึ่งถูกตัด text ออกแล้ว ทำให้ตรวจ clause ไม่เจอ แก้ให้ตรวจ retained source rows แล้วส่ง no_answer mode / warning / trace ตรงกับข้อความตอบ

## 5. ความช้าจากการเลือกหมวดซ้ำ
ใน r25 คำถาม RoV พร้อมคำเกริ่นมี route กติกาอยู่แล้ว แต่ LLM intent ใช้ 8.0848 วินาทีจากรวม 8.5317 วินาที แล้วเลือก intent เดิม คำถาม Tekken settings ใช้ semantic route refiner 1.4204 วินาที ก่อน question frame จะล็อกกติกาภายหลัง

เพิ่มทางลัดเฉพาะเมื่อมีเกมเดียวที่รู้จัก + สัญญาณกติกา + facet ชัด สร้าง intent ที่มี game/rulebook/facet แล้วข้ามการค้นหมวดและ LLM intent ซ้ำ ไม่ข้าม scope/freshness/ambiguity/evidence coverage/answer validation ชื่อเกมและ facet เป็นหลักฐานสำหรับ routing เท่านั้น ไม่ได้ทำให้ข้อกฎนั้นมีอยู่จริง

ตรวจ 12 request เทียบเว็บ r25 กับ r26: r25 median 0.3689s, max 7.2289s และขอ LLM intent 6 ครั้ง (บางครั้ง cache hit); r26 candidate median 0.3561s, max 1.7231s และขอ LLM intent 0 ครั้ง คำเกริ่นใหม่ RoV 7.2289 → 0.3664s; Tekken ประมาณ 2.8 → 0.3s การใช้งานครั้งแรกมีค่าเริ่มต้น/โหลดข้อมูล จึงไม่อ้างว่าทุกคำถามจะเสร็จภายใน 0.3s

## 6. ข้อผิดพลาดในตัวทดสอบ
Baseline 80 เคสผ่านดิบ 68/80 แยกได้ 5 เคสที่ oracle คาด “ไม่สามารถ” แต่ข้อกฎไทยจริงใช้ “ไม่อนุญาต” และคำตอบมีข้อห้ามพร้อมตัดสิทธิ์ถูกอยู่แล้ว แก้ fixture v2 โดยรักษา fixture v1 และ baseline ดิบ; อีก 7 เคสเป็นคำตอบบกพร่องจริง

การตรวจเวอร์ชันแรกยังยอมให้ first line เป็น heading/hardware หากเนื้อหาท้ายมี FT2 จึงเพิ่ม fixture v3 ตรวจประโยคแรก เก็บผลรอบ D ที่ผ่านเพียง 75/80 ไว้เป็นหลักฐานว่าเกณฑ์ใหม่จับจุดที่เคยมองข้ามได้

GT ใหญ่เดิม 2,000 เคสใช้ source overlap ไม่ใช่คะแนน semantic เต็ม: 30 เคสอังกฤษ Tekken อ้าง clause “PlayStation 5 console used” ที่สั้น 5 tokens แต่เกณฑ์ตรวจ window 7 tokens; 17 เคส VALORANT มี 5 penalty clauses จริง แต่เกณฑ์เลือก source line รับเฉพาะบาง modal/numeric words จึงตัด penalty clauses ทิ้ง ให้ผล fail ทั้งที่พบ literal clause ครบในคำตอบ

review แยกเก็บข้อกฎเต็ม + source hash เพื่อยืนยันเฉพาะ source presence ของ 47 เคสนี้ ไม่มีการเติมคำยาวในคำตอบเพื่อเอาคะแนน ไม่มีการเปลี่ยน Gold และไม่ใช้ review นี้อ้างว่ารายละเอียดทุกข้อของ 2,000 คำตอบถูกครบ

## 7. ข้อความแจ้งเตือนในหน้าเว็บ
ตรวจ UI จริงพบว่าคำถามมีตัวซ้ำตอบสำเร็จแล้ว แต่ notice ยังขอให้พิมพ์ใหม่ แก้ copy ไทย/อังกฤษให้บอกว่าพบตัวซ้ำและระบบประมวลผลต่อแล้ว พร้อมให้ตรวจว่าคำตอบตรงความต้องการ คง guard และข้อมูลดิบใน log ตามเดิม

## 8. Timeout หนึ่งครั้งในรอบ B
R24-TH-tekken8-105 ได้ request_timeout_no_answer ที่ 719.2584s แต่ stage split_multi_question ที่บันทึกใช้เพียง 18.62ms; global_elapsed 719.2565s ตั้งแต่ก่อนเข้าส่วนค้นข้อกฎ จึงยังไม่มีหลักฐานว่าเป็นความผิดของ scoring หรือ LLM และระบุต้นเหตุเครื่อง/การพักโปรเซสแน่ชัดไม่ได้

รีเทสเคสนี้ตอบผ่านใน 1.5759 วินาที รอบ C ไม่พบ timeout นี้อีก เก็บผล B ดิบ 1952/2000 และ 48 fails ไว้ ไม่เปลี่ยนเป็นผ่านย้อนหลัง ถ้าเกิดซ้ำควรเพิ่ม timing รอบ preprocessing/preflight และตรวจเหตุการณ์พักเครื่อง/โปรเซสในช่วงเวลาเดียวกัน

## 9. สิ่งที่อัตโนมัติยืนยันได้ และสิ่งที่ยังต้องตรวจ
อัตโนมัติ: source IDs ตรงเกม, clause/value/unit เฉพาะประเด็นใน fixture, รายการ penalty ครบ 5, ตาราง CS2 9 คู่, first-line facet, no_answer mode, no wrong pause subtype, routes ที่ต้องถามกลับ, hash ไฟล์ที่ป้องกัน, package code ตรง snapshot

ผู้ช่วยตรวจ: ต้นฉบับก่อนแก้ fixture, literal full clauses ของ 47 source-overlap failures, หน้าแชทและ notice ไทย/อังกฤษ การตรวจนี้ยังไม่ใช่คนใช้งานจริงหรือเจ้าของศูนย์รับรอง

เจ้าของ/ผู้จัดยังไม่ยืนยัน: ความขัดกันของ Tekken s03/s07 เรื่อง pause และหน่วยบทลงโทษ, V2 104 รายการในคิว review, การรับรองคำแปลอังกฤษอย่างเป็นทางการ และความเป็นปัจจุบันของกติกาแต่ละรายการ

## 10. ลำดับงานถัดไป
1. ขยาย proposition fixtures ด้วยคำถามและ log ของผู้ใช้จริงเมื่อเก็บได้ เน้นเงื่อนไขและข้อยกเว้น ไม่ใช้แค่เพิ่มจำนวน mutation ของ seed เดิม
2. ปรับตัวประเมิน overlap เป็น atomic source claims แล้วเพิ่ม assertions เนื้อหาเฉพาะประเด็นทีละ facet โดยเก็บคะแนนเดิมเทียบได้
3. ทำ clause coverage ให้กว้างกว่า age/pause/penalty/format ที่ตรวจในรอบนี้; หัวข้อกว้างอื่นยังต้องทดสอบรายละเอียดเฉพาะเพิ่มเติม
4. ถ้าพบ timeout ซ้ำ เก็บ timeline รอบ preflight และข้อมูลเหตุการณ์เครื่อง ไม่แก้ timeout limit โดยเดา
5. ขอผู้จัดตัดสิน Tekken: s07 เป็นข้อยกเว้น s03 หรือไม่ ต้องได้อนุญาตกรรมการหรือไม่ และ intentional/unnecessary pause เสีย Round, Game หรือ FT2 Match ในแต่ละกรณี
6. เก็บ V2 review queue ไว้จนกว่าจะตรวจรับรอง; ไม่เปิดใช้เพียงเพราะคำถามใกล้เคียงกับข้อมูล draft
