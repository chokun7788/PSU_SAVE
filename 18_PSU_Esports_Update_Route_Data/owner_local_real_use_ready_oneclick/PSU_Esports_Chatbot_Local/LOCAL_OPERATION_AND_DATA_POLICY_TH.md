# การใช้งานจริงแบบ Local และข้อมูลสนทนา

## รูปแบบการใช้งานของชุดนี้

ชุดนี้ทำงานบนเครื่องเดียวและเปิดเว็บที่ `http://127.0.0.1:8080/` เท่านั้น จึงเหมาะสำหรับเจ้าของระบบหรือผู้ทดสอบที่ใช้งานบนเครื่องนั้น ไม่เปิดรับผู้ใช้จากอินเทอร์เน็ตหรือเครือข่ายภายในองค์กร

Local LLM, RAG index, SQLite และ log ทั้งหมดอยู่ในโฟลเดอร์นี้ ไม่มี Cloud Chatbot API ในเส้นทางตอบคำถาม

## Session และการรีเฟรชหน้า

- เมื่อเปิดเว็บครั้งแรก ระบบจะสร้าง Session ID แบบสุ่มสำหรับ browser profile นั้น
- Session ID จะถูกเก็บใน Local Storage ของ browser เพื่อให้กด refresh หรือปิดแล้วเปิดแท็บเดิมได้โดยบทสนทนายังอยู่
- ข้อความที่เพิ่งส่งจะถูกเก็บใน browser ทันที และ server จะเก็บ transcript หลักใน SQLite
- เมื่อเปิดเว็บใหม่ หน้าเว็บจะอ่าน transcript ของ Session เดิมจาก `data\logs\chat_history.sqlite3` กลับมา
- ปุ่ม `ล้าง / Clear` เริ่มบทสนทนาใหม่ด้วย Session ID ใหม่ แต่ไม่ลบ log เดิม เพื่อรักษา audit trail

## ข้อมูลที่ระบบบันทึก

ต่อหนึ่งคำถาม ระบบบันทึก Session ID, เวลา, ข้อความผู้ใช้, คำตอบ, ภาษา, route, mode, ความเชื่อมั่น, เวลาใช้ตอบ, แหล่งอ้างอิง และสถานะข้อผิดพลาดถ้ามี

ไฟล์ที่เกิดขึ้นจริง:

- `data\logs\chat_history.sqlite3`: ฐานข้อมูล transcript และ session
- `data\logs\web_chat_YYYY-MM-DD.jsonl`: event log รายวันสำหรับตรวจสอบเชิงเทคนิค
- `data\logs\chat_history_report.html`: รายงานที่สร้างเมื่อเปิด `View-Chat-Logs.cmd`

## วิธีเปิดดู Log

1. ปิดหน้าเว็บหรือปล่อยให้ระบบทำงานได้ตามปกติ
2. ดับเบิลคลิก `View-Chat-Logs.cmd`
3. Browser จะเปิดรายงาน HTML ที่จัดกลุ่มตาม Session และมีข้อความเต็มของบทสนทนา

รายงานนี้เป็นข้อมูลลับ เพราะผู้ใช้อาจพิมพ์ข้อมูลส่วนบุคคลลงในแชต ห้ามส่งฐานข้อมูลหรือรายงานออกนอกผู้ดูแลที่ได้รับอนุญาต

## การสำรองและการเก็บรักษา

- สำรองเฉพาะ `data\logs\chat_history.sqlite3` ขณะปิดระบบแล้ว เพื่อหลีกเลี่ยงการคัดลอกระหว่างมีการเขียนข้อมูล
- ชุดนี้ยังไม่ลบประวัติอัตโนมัติ ผู้ดูแลต้องกำหนดระยะเวลาเก็บข้อมูลกับหน่วยงานก่อนเปิดบริการจริง
- หากต้องล้างประวัติทั้งหมด ให้หยุดระบบก่อนและย้าย `data\logs\chat_history.sqlite3` ไปเก็บในที่ปลอดภัย ไม่ควรลบทิ้งโดยไม่มีนโยบายอนุมัติ

## ข้อจำกัดด้านความปลอดภัย

ชุด Local นี้ไม่มีระบบ Login เพราะ bind ไว้ที่ `127.0.0.1` และออกแบบให้เจ้าของเครื่องใช้เองเท่านั้น หากจะเปิดให้เครื่องอื่นหรือสาธารณะใช้ ต้องเปลี่ยนเป็น production deployment ที่มี HTTPS, Login, server-side session, Postgres, retention policy, rate limit และสิทธิ์ดู log แยกตามบทบาทก่อน
